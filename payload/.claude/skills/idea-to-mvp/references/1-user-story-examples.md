`1-user-story.md` §2.2에서 쓰는 예시 모음이다. 모양(단면·양면·조직 안·외부 플랫폼·여럿의 조율·외부 기관과 사람 개입)이 고루 섞이게 골랐다.

**쓰는 규칙** (자세한 건 `1-user-story.md` §2.2):

- 4번 질문에 붙이는 채운 예는 **사용자 아이디어와 다른 분야 하나만** 골라 "분야가 다르니 모양만 참고해"라고 붙인다. 같은 분야 예시는 답을 그쪽으로 끌고 간다.
- 「무엇을 넣나」「무엇이 되어, 어디에 남나」 설명에 붙이는 짝 예시도 사용자 분야가 아닌 것에서 3개 안팎을 고른다.
- 답이 뭉개졌을 때("AI가 알아서 해 준다") 내미는 후보는 이 모음에서 고르지 않는다 — 그 사람의 3번 답에서 뽑아 흐름 2~3개로 만든다.

## ① 인테리어 견적 요청 — 사용자와 관리자

- **3번**: 문제 — 업체마다 전화로 원하는 공사를 설명해야 한다 / 불편 — 같은 설명을 반복하고, 받은 견적의 형식이 제각각이라 비교가 어렵다 / 때우는 방법 — 메모장에 요구사항을 적어 두고 불러 주고, 받은 견적을 엑셀에 옮겨 비교 / 실제 한 번 — 지난봄 욕실 공사 때 세 곳에 전화하다 한 곳엔 예산을 잘못 말해 견적을 다시 받았다
- **4번**:

  ```
  [1] 리모델링을 앞둔 집주인이 → 평수·원하는 공사·예산을 적고 현장 사진을 올린다 → 사이트에 견적 요청 한 건으로 접수된다
  [2] 업체 관리자가 요청 목록에서 그 건을 열어 → 항목별 공사 금액을 적는다 → 견적서가 되어 집주인에게 보내진다
  [끝] 집주인이 견적서를 받아 → 업체들을 비교하고 한 곳에 상담을 신청한다
  ```

## ② 동네 중고 거래 — 파는 사람과 사는 사람 (양면)

- **3번(파는 사람)**: 문제 — 안 쓰는 물건이 쌓인다 / 불편 — 올릴 때마다 사진·설명을 새로 쓰고, 문의에 제때 답하기 어렵다 / 때우는 방법 — 아파트 단체 대화방에 사진을 올린다 / 실제 한 번 — 유모차를 올렸는데 문의 여섯 개가 대화방에 섞여 누구와 약속했는지 헷갈렸다
- **4번**:

  ```
  [1] 파는 사람이 → 사진·가격·설명을 올린다 → 매물 글 한 건이 동네 목록에 올라간다
  [2] 사는 사람이 동네 매물 목록에서 그 글을 보고 → 문의를 보낸다 → 대화 한 건이 생긴다
  [3] 파는 사람이 → 답하고 시간·장소를 정한다 → 거래 약속 한 건이 된다
  [끝] 거래가 끝나면 → 파는 사람에게 판매 완료 표시, 사는 사람에게 구매 내역이 남는다
  ```

## ③ 사내 휴가 신청 — 직원·팀장·인사 시스템 (조직 안)

- **3번**: 문제 — 휴가를 쓰려면 종이 양식에 적어 팀장 자리에 가져가야 한다 / 불편 — 팀장이 자리에 없으면 며칠씩 밀리고, 남은 연차를 따로 물어봐야 안다 / 때우는 방법 — 메신저로 먼저 말해 두고 양식은 나중에 낸다 / 실제 한 번 — 지난달 가족 행사 휴가를 메신저로만 말해 뒀다가 양식이 빠져 결근으로 처리될 뻔했다
- **4번**:

  ```
  [1] 직원이 → 날짜·휴가 종류·사유를 고른다 → 신청서 한 건이 팀장 결재함에 들어간다
  [2] 팀장이 결재함에서 그 신청서를 열어 → 승인하거나 반려한다 → 승인된 신청이 된다
  [3] 인사 시스템이 → 승인된 만큼 연차를 뺀다 → 남은 연차가 갱신된다
  [끝] 직원에게 → 승인 알림과 갱신된 남은 연차가 돌아온다
  ```

## ④ 블로그·SNS 글 발행 — 작성자와 외부 플랫폼

- **3번**: 문제 — 같은 글을 블로그와 인스타그램에 따로 올려야 한다 / 불편 — 플랫폼마다 사진 크기·글 길이가 달라 매번 다시 손본다 / 때우는 방법 — 블로그에 먼저 쓰고 인스타그램용은 휴대폰에서 줄여 다시 쓴다 / 실제 한 번 — 여행 글을 올리고 인스타그램용을 미루다가 일주일 뒤에야 올렸다
- **4번**:

  ```
  [1] 작성자가 → 글을 쓰고 사진을 골라 넣고, 올릴 곳을 고른다 → 발행 대기 글 한 편이 된다
  [2] 서비스가 → 플랫폼마다 사진 크기와 글 길이를 맞춰 올린다 → 블로그에 포스트 한 편, 인스타그램 피드에 게시물 한 건이 올라간다
  [3] 독자가 → 댓글을 달거나 좋아요를 누른다 → 글마다 반응이 쌓인다
  [끝] 작성자에게 → 올라간 글 주소와 반응 모음이 돌아온다
  ```

## ⑤ 모임 날짜 잡기 — 모임장과 참석자 여럿

- **3번**: 문제 — 다섯 명 이상 날짜를 맞추기 어렵다 / 불편 — 대화방에서 날짜를 하나씩 물으면 답이 섞이고 며칠이 간다 / 때우는 방법 — 모임장이 표를 만들어 대화방에 올리고 손으로 센다 / 실제 한 번 — 동창 모임 날짜를 정하는 데 열흘이 걸렸고, 한 명은 정해진 뒤에야 안 된다고 했다
- **4번**:

  ```
  [1] 모임장이 → 참석자와 후보 기간을 넣는다 → 날짜 투표 한 건이 참석자들에게 간다
  [2] 참석자가 각자 → 되는 날을 표시한다 → 응답이 모인다
  [3] 서비스가 → 모두 되는 날을 추린다 → 후보 날짜 몇 개가 된다
  [4] 모임장이 → 하나를 고른다 → 확정 일정이 된다
  [끝] 참석자 모두의 달력에 → 일정 한 건이 들어간다
  ```

## ⑥ 서류 제출 대행 — 사용자·서비스·외부 기관 사이트 (사람이 중간에 끼어듦)

- **3번**: 문제 — 기관 사이트마다 로그인 방식과 제출 화면이 다르다 / 불편 — 한 번 제출하려면 공동인증서·본인확인을 거치고 파일 형식을 맞추느라 한 시간이 간다 / 때우는 방법 — 서류를 스캔해 폴더에 모아 두고, 제출은 주말에 몰아서 한다 / 실제 한 번 — 마감 전날 밤에 제출하다가 파일 용량 제한에 걸려 다시 스캔했다
- **4번**:

  ```
  [1] 사용자가 → 제출할 기관과 서류 종류를 고르고 스캔 파일을 올린다 → 제출 준비 한 건이 된다
  [2] 서비스가 → 기관 사이트에 로그인을 시도한다 → 본인확인 요청이 사용자 휴대폰에 온다
  [3] 사용자가 → 휴대폰에서 본인확인을 승인한다 → 로그인이 끝난다
  [4] 서비스가 → 서류를 첨부해 제출한다 → 기관 사이트에 접수 한 건(접수번호)이 남는다
  [5] 기관 담당자가 → 서류를 심사한다 → 처리 결과가 나온다
  [끝] 사용자에게 → 접수번호와 처리 결과 알림이 돌아온다
  ```
