## 1. 감지 — 왜 빈 곳 3번 연속 터치인가

- **길게 누르기는 아이폰에서 안 된다(실측 2026-10-22).** 빈 곳을 1초 눌러도 사파리가 가장 가까운 글자를 선택하려 해서(약 0.5초) 누르기가 취소됐다. 그래서 길게 누르기 코드는 모두 빼고 **빈 곳 3번 연속 터치**(PC는 세 번 클릭)로 바꿨다.
- **판정값** — 터치 3번 · 터치 사이(손 뗀 때부터 다음 손 뗀 때까지) 400ms 안 · 첫 터치 지점에서 30px 안(손가락 오차) · 누른 채 10px 넘게 움직이면 그 터치는 무효(스크롤·드래그). 스크롤·`pointercancel`·두 손가락·빈 곳 아닌 데 누르기·화면 가려짐·창이 열려 있음이면 처음부터 다시 센다.
- **3번째 터치를 따라오는 click** — 손을 뗀 직후 브라우저가 click을 보낸다. 그때 창 뒤 배경(누르면 닫히는 자리)이 이미 깔려 있으면 그 click이 배경을 눌러 창이 바로 닫혔다. 그래서 창을 연 뒤 400ms는 닫기를 무시한다.
- **「빈 곳」** — 버튼·링크·입력칸·그림 위와 **글자 줄 위**는 세지 않는다. 그 자리의 원래 동작(누르기·글자 선택·그림 저장 메뉴)이 그대로 나와야 해서다. 「글자 위」는 눌린 요소 바로 아래 글자 덩어리가 실제로 차지한 줄 칸(여유 4px)으로 판정한다 — 카드 여백·줄 끝 뒤 빈칸은 빈 곳으로 남는다. 커서 위치 API(`caretPositionFromPoint`)는 글자 없는 칸에서도 가까운 글자를 돌려주고 `user-select: none`에서 null이 와 흔들려서 쓰지 않는다. 일부러 뺄 곳은 `data-qa-ignore`.
- **두 번 톡 확대** — 같은 자리를 빠르게 두 번 톡 하면 아이폰이 확대한다. `html { touch-action: manipulation }`으로 두 번 톡 확대만 끈다. 두 손가락 확대는 남는다. **뷰포트 meta로 확대를 막지 않는다** — 글자를 키워 봐야 하는 사람이 있다(접근성).
- **글자 선택** — 세 번 터치로 생긴 선택은 창을 열 때 지운다(캡처에 찍히지 않게).
- **브라우저별로 남은 것** — 아이폰은 터치 이벤트 안에서 연 창이 아니면 자판이 저절로 안 올라올 수 있다(입력칸에 초점만 두고, 안 올라오면 한 번 눌러 쓰게 둠). 안드로이드 크롬의 기본 메뉴·글자 선택 손잡이, 카톡 안 브라우저, 키보드만 쓰는 사람(못 연다 — 내부 시험 도구라 넣지 않음)은 §10 실측 목록.

## 2. 캡처 — DOM을 다시 그린다

### 2.1 왜 진짜 스크린샷이 아닌가

- 웹은 휴대폰 화면을 찍을 수 없다. 화면 공유 API(`getDisplayMedia`)는 안드로이드 크롬·웹뷰에서 지원하지 않고, 아이폰은 쓸 때마다 허용 창과 화면 고르기가 떠서 「누른 순간」을 찍는 데 맞지 않는다.
- 그래서 **지금 DOM을 그림으로 다시 그리는** `modern-screenshot`을 쓴다. 화면을 복제해 SVG `foreignObject` 안에 넣고 브라우저가 그리게 하는 방식이라 CSS 변수·컨테이너 쿼리·`filter`가 그대로 나온다. 비교한 후보: `html-to-image`(더 작지만 사파리 대응이 얕음), `html2canvas`(2022년 뒤 멈춤, 흉내 방식이라 `filter`를 못 그림), `html2canvas-pro`(가장 큼). `modern-screenshot`은 사파리 대응 옵션·복제본 손질 훅(`onCloneNode`·`onCloneEachNode`)·거르기(`filter`)가 있어 아래 문제를 풀 수 있었다.
- 일반 사용자 첫 화면 번들에 안 들어가게 **동적 import**한다. 감지가 켜지면 브라우저가 한가할 때(`requestIdleCallback`) 미리 받아 두고, 3번째 터치 순간 미리 받은 코드가 있으면 그 자리에서 바로 부른다.

### 2.2 아이폰(WebKit)에서만 깨진 네 가지

PC 크롬에선 그대로 잘 찍혔는데 아이폰에서만 깨졌다. 모두 `capture.ts`에서 고쳤고 크롬도 같은 방식으로 맞게 찍힌다.

| 증상 | 원인 | 대응 |
|---|---|---|
| 스크롤한 뒤 찍으면 **아래 절반이 검다** | 복제본을 스크롤만큼 옮겨(`transform`) 찍으면 WebKit은 옮긴 복제본의 원래 상자 밖을 그리지 않는다 | 복제본을 옮기지 않는다. 문서 맨 위부터 「스크롤 위치 + 화면 높이」까지 그린 뒤, 캔버스에서 보이던 구간만 잘라 낸다 |
| **왼쪽에 검은 세로 띠** | JPEG는 투명한 곳을 검게 만드는데, 라이브러리가 사파리용으로 캔버스를 지웠다 다시 그리며 바탕색을 지운다. 그림 안 body에 기본 바깥 여백(8px)이 붙는다 | 잘라 낸 캔버스를 **페이지 바탕색으로 먼저 칠한 뒤** 그린다. 복제본 body 바깥 여백 0. 창이 건 스크롤 잠금(`overflow: hidden`)도 복제본에선 푼다 |
| **아래 sticky 탭바가 빠진다** | 복제본은 맨 위부터 그려져서 sticky가 그 순간 옮겨 놓은 자리가 사라진다. relative로 옮기는 방법은 아이폰에서 탭바를 안 그렸다 | 찍는 순간 sticky·fixed 요소의 화면 위치를 재 두고, 복제본에서 그 자리에 `absolute`로 고정. sticky가 차지하던 흐름 속 자리엔 같은 크기 빈 칸을 남긴다. 클래스 이름이 아니라 계산된 `position`으로 찾는다 |
| `box-shadow: 0 0 0 Npx 색` **고리가 반달처럼 어긋난다** | WebKit이 그림 안에서 흐림 없는 고리를 옆으로 밀어 그린다(실제 화면은 정상) | 복제본에서만 맨 위 그림자 층이 고리면 `outline: Npx solid 색`(`outline-offset: 0`)으로 바꿔 그린다. 흐림 있는 그림자·아래 층은 그대로 |

그래서 확인 절차(SKILL.md 단계 5)가 아이폰 「스크롤 안 함 / 중간 / 맨 아래」 + PC를 따로 보낸다.

### 2.3 글꼴과 상한

- **글꼴** — 이 방식은 글꼴을 그림 안에 통째로 넣어야 한다. 조각(unicode-range) 글꼴은 라이브러리에 맡기면 조각 수백 개를 다 받아 넣어 휴대폰에서 몇 MB·몇 초가 된다. 그래서 브라우저가 **이미 받아 둔 조각만**(`document.fonts`에서 `loaded`) 골라 캐시에서 꺼내 넣는다. 같은 출처 글꼴만 넣는다 — 다른 사이트(CDN)에서 받는 글꼴은 캡처에서 기본 글꼴로 나온다(`next/font`는 같은 출처라 괜찮다).
- **상한** — 배율 최대 2 · JPEG 품질 0.8(사파리는 캔버스에서 WebP를 못 만들 수 있어 JPEG) · 1.5MB 넘으면 배율 1로 다시 만들기 · 중간 캔버스 1,200만 픽셀·한 변 16,000px(iOS 캔버스 넓이 한도 약 1,677만 픽셀 아래). 깊이 스크롤해 넓이가 넘으면 배율을 낮춘다.

### 2.4 찍는 순서

1. 3번째 터치를 뗀 순간 스크롤 위치·화면 크기·sticky 위치를 재고 캡처를 **시작**한다(기다리지 않음).
2. 바로 창을 연다 — 사용자가 쓰는 동안 캡처가 끝난다. 창·토스트·Next 개발 표시는 캡처에서 뺀다.
3. 보낼 때 캡처가 아직이면 최대 3초 기다리고, 실패·시간 초과면 **글만 보낸다** — 이슈엔 「캡처 실패 — 이유」가 들어간다. **캡처가 실패해도 이슈는 만든다.**
4. 창에 캡처 미리보기는 보여 주지 않는다. 대신 「화면 사진과 기기 정보가 함께 간다」는 안내 한 줄을 둔다.

## 3. 이미지 보관처 — 별도 비공개 저장소

- **GitHub API로는 이슈에 그림을 직접 첨부할 수 없다.** 드래그해 올리는 첨부(`user-attachments`)는 브라우저 로그인 세션에 묶여 있고 공개 API가 없다. 그림을 글자로 바꿔 넣는 것(data URI)도 GitHub가 그리지 않는다. 그래서 그림을 어딘가에 올리고 본문에서 주소로 불러야 한다.
- **GitHub 바깥에 둔 그림은 익명 중계 서버(Camo)를 거친다** — GitHub가 바깥 그림을 대신 받아 보여 주므로, 바깥 보관처는 「주소만 알면 누구나 보는」 곳이어야만 이슈에 보인다. 공개 버킷(Supabase·Vercel Blob)은 주소가 새면 로그인 없이 열린다. 서명 주소는 기한이 지나면 이슈의 그림이 깨진다.
- 캡처에는 사용자 이름·얼굴·대화가 찍힌다. 비공개로 지키려면 **GitHub 저장소에 커밋**하는 것뿐이다 — 그 저장소 권한이 있는 로그인 사용자에게만 보인다.
- **코드 저장소가 아니라 별도 비공개 캡처 저장소**에 커밋한다. 같은 저장소의 다른 브랜치에 커밋하면 커밋마다 미리보기 빌드가 돌고, 코드 저장소에 Contents 쓰기 토큰이 필요해진다(§4).
- 그림 주소는 Contents API 응답의 `content.html_url`에 `?raw=true`를 붙여 만들고, 모양을 검사한 뒤에만 건다. 파일 이름은 서버가 만든다(`2026/10/22/<무작위 id>.jpg`). 커밋 메시지엔 경로만 — 사용자 글은 넣지 않는다. 같은 저장소에 동시에 쓰면 409가 날 수 있어 한 번만 다시 시도한다.
- **지우기** — git 기록에 남아서 파일만 지워선 사라지지 않는다. 정식 공개 때 **캡처 저장소를 통째로 지우는 것**으로 정리한다(그때 이슈의 그림은 깨진다 — 필요한 이슈는 먼저 처리).

## 4. 토큰 — 저장소 하나·권한 하나씩 둘

- 세분화 토큰은 **고른 저장소 전부에 같은 권한**이 붙는다. 하나로 두 저장소를 고르면 코드 저장소에도 Contents 쓰기가 생긴다. 무료 조직의 비공개 저장소는 main 보호 규칙을 못 켜서, 그 토큰이 새면 main에 바로 밀려 실서비스까지 배포될 수 있다. 그래서 둘로 나눈다.
  - 이슈용 `GITHUB_QA_ISSUE_TOKEN` — 코드 저장소 하나, **Issues 쓰기만**
  - 캡처용 `GITHUB_QA_SHOTS_TOKEN` — 캡처 저장소 하나, **Contents 쓰기만**(그림만 있는 저장소라 새도 피해가 그 안에 머문다)
- **GitHub 앱이 아닌 이유** — 앱은 사람 계정에 안 묶이고 작성자가 봇으로 찍혀 깔끔하지만, 조직 소유자가 앱을 만들어 설치해야 하고 서명(JWT) 코드가 는다. 정식 공개 때 뺄 기능이라 토큰 둘로 충분하다.
- **조직 토큰은 소유자 승인이 필요할 수 있다**(조직 기본값). 작업 계정이 일반 member면 토큰이 Pending으로 남고, 그동안 GitHub는 **404**로 거절한다(비공개 저장소는 권한이 없으면 존재를 숨긴다). 404가 나면 먼저 Pending인지 본다. 승인 요청 글에는 「무슨 토큰인지 · 권한이 얼마나 좁은지 · 왜 막혀 있는지 · 어디서 승인하는지 · 언제든 끊을 수 있음」을 담아야 소유자가 이해한다(`human-setup.md` 5.2).
- 토큰 둘·저장소 둘 중 **하나라도 비어 있으면** GitHub를 부르지 않고 성공으로 답하며 「이렇게 만들 뻔했어요」 로그만 남긴다 — 로컬 기본값이고, 1차 실측(단계 4)이 이 상태로 돈다. 저장소 이름이 `owner/repo` 모양이 아니면 잘못 넣은 설정이라 실패로 답한다(「보냈다」고 뜨는데 이슈가 없는 일이 없게).

## 5. 두 방식 — 로그인 없는 방식과 로그인 방식

참고 구현은 로그인 방식 하나뿐이었다. 하지만 idea-to-mvp로 보면 Vercel 주소가 처음 생기는 5단계(프론트 프로토타입)에 피드백이 가장 필요하고, 로그인은 6단계에서 붙는다. 그래서 두 방식을 다 깔 수 있게 했다.

|  | 로그인 없는 방식 (`anon`) | 로그인 방식 (`auth`) |
|---|---|---|
| 필요한 것 | GitHub 저장소 + Vercel 배포. DB·인증 없음 | 위 + 프로젝트의 인증 |
| 누가 보내나 | 링크를 연 누구나 | 로그인한 사람만 |
| 감지를 켜는 조건 | 스위치만 켜져 있으면 늘 | 스위치 + 로그인 확인 뒤 |
| 남발 막기 | 접속 IP 기준 30초 1번·하루 20번 | 계정 기준 30초 1번·하루 20번 |
| 이슈의 사람 정보 | 「보낸 사람: 로그인 없는 방식」 한 줄 — 테스터에게 글 앞에 이름을 부탁 | 계정 id · 팀 · 팀에서 부르는 이름 |
| 같은 출처 검사 | Origin 머리글이 **없어도** 거절(누구나 부를 수 있는 주소라 조인다) | Origin이 있으면 같아야 함 |
| IP | 한도 계산에만 쓴다. 원문은 메모리에도 두지 않고 인스턴스마다 새로 정한 소금값과 함께 해시. 로그·이슈엔 안 넣는다 | 쓰지 않는다 |

- **두 방식에 똑같이 적용하는 것** — 스위치, 같은 출처 검사, 크기·길이 한도, 이슈 본문 안전 처리, 주소 가리기, 캡처 실패해도 이슈, 캡처 비공개 저장소, 토큰 둘, 로그 금지 항목, 처리방침 머지 전 확인.
- **코드에서 나누는 법** — 갈리는 자리는 서버 `reporter.ts`(누구인가) 하나와 화면 `gate.ts`(감지를 켜도 되나) 하나뿐이다. 나머지 파일은 같다. 환경변수로 방식을 고르지 않는다 — 로그인 방식 코드는 인증 모듈을 import해서 인증이 없는 5단계 프로젝트에선 빌드가 깨지고, 환경변수 하나로 실서비스가 조용히 「누구나 보내기」로 바뀔 위험이 있어서다. 두 파일의 `QA_REPORTER_MODE`가 지금 방식을 드러낸다.
- **로그인 없는 방식의 약점** — 실서비스 주소를 아는 누구나 보낼 수 있고, IP를 바꿔 가며 보내면 IP 한도는 의미가 없다. 그래서 인스턴스 전체 상한(한 시간 60번)을 두고, 테스터 안내에 「주소를 아무 데나 올리지 말라」를 넣고, 정식 공개(광고) 전에 끈다.

## 6. 서버 확인 순서와 한도

**순서** — 스위치(`QA_FEEDBACK !== "on"`이면 404 — 없는 주소처럼) → 같은 출처(403 — 로그인 쿠키를 쓰는 POST를 다른 사이트가 몰래 보내게 하는 공격 막기) → 요청 크기(`Content-Length` 4MB 넘으면 본문을 읽기 전에 413) → 누구인가(로그인 방식만 — 로그인·탈퇴 확인, 없으면 401) → 연속 제출(429) → 내용(400) → 그다음에만 GitHub를 부른다.

| 항목 | 한도 | 이유 |
|---|---|---|
| 한 줄 글 | 1~200자, 줄바꿈·제어 문자 제거. 빈 글이면 400 | 「한 줄」이 목적. 화면 입력칸에도 `maxLength`를 걸지만 서버가 다시 본다 |
| 캡처 | JPEG만(앞 3바이트 `FF D8 FF`), 2MB 이하. 아니면 캡처만 버리고 글은 보냄 | 화면이 보낸 종류·이름은 믿지 않는다 |
| 화면 정보(meta) | JSON 4KB 이하, 정해 둔 칸만 꺼내고 칸마다 길이 제한 | 나머지 칸은 버린다. 보낸 사람 정보는 화면에서 받지 않는다 |
| 요청 전체 | 4MB | **Vercel 함수 요청 본문 한도가 4.5MB** — 그 위는 Vercel이 먼저 413으로 끊는다 |
| 같은 보낸 사람 | 30초에 1번, 하루 20번 | 실수로 두 번 누름·장난 막기 |
| 인스턴스 전체 | 한 시간 60번 | 보낸 사람을 바꿔 가며 쏟아 넣는 것을 GitHub 한도 앞에서 끊기 |
| GitHub 쪽 | 「내용을 만드는 요청」 분당 80·시간당 500 | 넘으면 토큰 계정에 불이익이 올 수 있다. 429·403은 다시 시도하지 않는다 |

- **연속 제출 기록은 서버 메모리**다 — 함수 인스턴스마다 따로 세서, 인스턴스가 여럿이거나 새로 뜨면 한도가 풀린다. 완전하지 않다. DB에 두면 마이그레이션이 생겨 정식 공개 때 빼기가 무거워져서 메모리로 뒀다. 마지막 벽은 GitHub 한도다.
- **실패한 제출도 「30초 1번」에 센다** — GitHub를 부르기 전에 세기 때문이다. 토큰 문제로 실패한 직후 다시 누르면 「조금 뒤에 다시」가 떠서 원인이 가려진다(실측). 그래서 실패하면 화면 문구보다 서버 로그부터 본다(`human-setup.md` 9).
- GitHub 호출 시간 제한 — 캡처 커밋 6초(409로 다시 해도 최대 2번), 이슈 10초, 라벨 5초. 함수 전체(`maxDuration` 30초) 안에 든다.
- 라벨 — GitHub 문서상 푸시 권한이 없는 토큰으로 이슈를 만들면 라벨을 조용히 버린다. 응답에 라벨이 없으면 「라벨 붙이기」를 한 번 더 부른다. 그것만 실패하면 이슈는 이미 있으니 성공으로 본다.

## 7. 이슈 모양과 안전 처리

**모양** — 제목 `[QA] {글 앞 40자}`, 라벨 `qa`. 본문: 남긴 말(코드 블록) → 캡처 그림(`github.com/.../blob/...jpg?raw=true`) 또는 「캡처 실패 — 이유」 → 표(화면 주소 · 기기·브라우저 · 화면 크기·배율·확대·스크롤 · 보낸 사람 줄 · 시각(서버·휴대폰 둘 다 — 휴대폰 시계가 틀린 경우도 보이게) · 배포(환경·브랜치·커밋·「화면이 옛 배포」 표시)) → 기계가 읽는 HTML 주석 한 줄(`qa-meta` — 나중에 AI가 모인 이슈를 처리할 때 쓰려고 미리 넣어 둠). 계정·팀 id는 사람을 찾아 고칠 때 쓰니 줄이지 않고 전체를 적는다. 이슈 번호·주소는 화면에 돌려주지 않는다.

**안전 처리** — 사용자 글뿐 아니라 주소·UA·팀 이름·브랜치 이름도 바깥에서 온 글이다. `issue.ts` + 단위 시험(`npm run test:qa`)이 지킨다.

| 문제 | 대응 |
|---|---|
| 사용자 글의 멘션(`@누구`)·이슈 번호(`#12`)·그림·링크·HTML | 줄바꿈·제어 문자를 지워 한 줄로 만든 뒤 **코드 블록** 안에. 울타리는 글에 든 가장 긴 백틱 줄보다 하나 더 길게 |
| 제목(코드 블록을 못 씀) | `@`·`#` 뒤에 보이지 않는 띄움 문자(U+200B)를 넣어 연결을 끊는다. 40자에서 자르고 「…」 |
| 표 칸에 넣는 바깥 글 | 인라인 코드로 감싸고 백틱·세로줄·역슬래시·줄바꿈을 지운다(칸이 깨지거나 코드가 일찍 끝나지 않게). 커밋 링크는 값이 16진수 커밋 모양일 때만 |
| 기계용 묶음(HTML 주석) | JSON의 `<`·`>`를 `<`·`>`로 바꿔 `-->`가 끼지 못하게. 사용자 글은 넣지 않는다 |
| 그림 주소 | GitHub 응답에서만 받고 `https://github.com/…/blob/….jpg?raw=true` 모양이 아니면 걸지 않는다 |
| 주소 속 비밀값 | 초대 코드 같은 경로(`/invite/{code}` → `/invite/***`)와 `code`·`token` 쿼리 값을 가리고, `#` 뒤는 아예 안 보낸다(`mask-rules` 어댑터) |

## 8. 로그

- **남기지 않는다**: 글 내용 · 이미지 · 계정 id · 이메일 · 팀 이름 · 부르는 이름 · IP · 토큰 · 이슈 번호·주소 · GitHub 응답 본문.
- **남긴다**: 이슈 만들기 성공·실패, GitHub 응답 상태 코드(이슈·라벨·캡처), 캡처 바이트, 방식(`mode`).
- GitHub 설정이 없을 때의 「이렇게 만들 뻔했어요」 줄에는 확인용으로 빠진 설정 이름 · 글자 수 · 가린 주소 · 기기 한 줄 · 화면 크기 · 캡처 크기 · 배포만 넣는다.

## 9. 개인정보와 처리방침

- **무엇이 GitHub로 가나** — 캡처에는 그 화면에 보이던 것이 그대로 찍힌다. 보내는 사람 본인 것만이 아니라 **같은 화면에 보이던 다른 사람의 이름·글**도 간다. 로그인 방식이면 이슈 글에 계정 id·팀 이름도 들어간다. GitHub는 미국 회사다.
- **최소한만** — 이메일·IP는 넣지 않는다. 주소 속 비밀값은 가린다.
- **보는 사람을 좁힘** — 이슈는 코드 저장소, 캡처는 별도 비공개 저장소라 권한을 받은 사람만 본다.
- **보내는 사람에게 알림** — 창의 안내 한 줄(무엇이 함께 가는지). 로그인 없는 방식은 테스터 사전 안내도.
- **처리방침** — 「모으는 정보」(남긴 한 줄·화면 사진·기기 정보·화면 주소, 로그인 방식이면 계정 식별자) · 「쓰는 곳」(앱 문제를 고치는 데만) · 「보관 기간」(정식 공개 전에 모두 지움) · 「맡기는 곳」(GitHub, 미국 서버)에 한 줄씩. **머지 전에 넣는다.** 처리방침에 「이 밖의 다른 곳에 주지 않는다」 같은 문장이 있으면 넣지 않은 채로는 사실과 어긋난다. 처리방침 화면이 아직 없는 5단계는 안내 줄과 테스터 안내로 대신하고 6단계에서 처리방침을 만들 때 넣는다. 국외 보관 고지가 필요한지 같은 법적 판단은 이 스킬이 하지 않는다.
- **탈퇴와의 관계** — 탈퇴하면 글을 지운다고 약속한 서비스라도 캡처에 찍힌 글은 GitHub에 남는다. 그 전에 삭제 요청이 오면 해당 이슈와 캡처 파일을 사람이 지운다(캡처 저장소는 git 기록에 남으니 꼭 필요하면 저장소를 다시 만든다). 정식 공개 때 캡처 저장소 삭제·`qa` 이슈 정리를 함께 한다.
- **나중의 AI 처리**(범위 밖) — 밤마다 AI가 이슈를 읽게 되면 캡처 속 정보가 AI 제공사로도 간다. 그 흐름을 설계할 때 같이 본다.

## 10. 실측 기록 — 된 것과 아직인 것

**참고 구현에서 실측된 것** (로그인 방식, 자체 CSS 부품, 조직 저장소 + member 계정)

- 아이폰: 길게 누르기 실패 → 3번 연속 터치로 바꿔 동작.
- 아이폰: 캡처 깨짐 네 가지를 고친 뒤 정상, PC 크롬 정상.
- 조직 세분화 토큰: 조직 소유자 승인 뒤 동작(최대 366일). 승인 전 404.
- Vercel 환경변수 화면이 2026-10에 바뀜(`human-setup.md` 6.2).

**실측 필요** — 적용할 때 확인 절차(SKILL.md 단계 4·5)에서 보고, 결과를 프로젝트 `docs/qa-feedback.md`에 적는다. 하네스 쪽에서 확인되면 이 목록을 고친다.

1. 다른 비공개 저장소의 그림이 이슈에서 **웹과 GitHub 모바일 앱 모두** 보이는지.
2. Issues 쓰기 토큰으로 만든 이슈에 라벨이 바로 붙는지, 「라벨 붙이기」 재호출로 붙는지(로그의 `label` 값).
3. **하네스 고정 스택(Tailwind + shadcn)에서의 창** — 3번째 터치의 click이 창을 바로 닫지 않는지, 첫 초점이 입력칸으로 가는지, 창이 거는 스크롤 잠금이 캡처(특히 sticky 위치)에 끼어들지 않는지, 창 배경·토스트가 캡처에서 빠지는지. 참고 구현은 자체 CSS 부품이라 이 조합은 실측이 없다.
4. 아이폰 자판이 창을 열 때 저절로 올라오는지.
5. 아이폰 사파리·홈 화면 앱·카톡 안 브라우저·안드로이드 크롬에서 3번 터치가 창을 여는지, 두 번 톡 확대가 안 되는지, 글자·버튼·그림 위에선 원래 동작이 되는지.
6. 캡처 시간(휴대폰에서 몇 초)과 크기(JPEG 몇 KB), 프로젝트 글꼴이 캡처에 그대로 나오는지.
7. **로그인 없는 방식** — 모든 대상 브라우저가 같은 출처 `fetch` POST에 Origin 머리글을 붙이는지(안 붙이면 정상 사용자가 403), Vercel이 `x-forwarded-for`를 덮어써 위조를 막는지, 첫 화면부터 감지가 켜져도 평소 동작(스크롤 멈추려고 톡톡)과 부딪히지 않는지, 같은 와이파이 테스터들이 한도에 자주 걸리는지.
8. **Vercel 배포 보호** — 지금 프로젝트의 Deployment Protection 값, 실서비스 기본 주소가 열리는지, 보호를 켠 채 공유 링크로 열었을 때 보내기가 통과하는지.
9. Vercel 환경변수의 **Config 타입**으로 넣은 `QA_FEEDBACK`이 빌드에 들어가는지(창이 뜨면 들어간 것).
10. 개인 계정 저장소 갈래(승인 단계 없음으로 보고 설계함).
11. Supabase 밖 인증(NextAuth·Clerk 등) — 어댑터 자리만 있다.
