# qa-to-issue — 화면 3번 터치로 GitHub 이슈 남기기

웹앱 프로젝트에 이 기능을 깐다: 사용자가 화면 **빈 곳을 3번 연속 터치**(PC는 세 번 클릭)하면 한 줄 피드백 창이 뜨고, 보내면 그 순간의 **화면 캡처**와 기기·배포 정보가 붙은 **GitHub 이슈**(`qa` 라벨)가 생긴다. 참고 구현은 상식이 퀴우기(2026-10, 실서비스에서 돌고 있음)이고, 거기서 실기기로 겪은 시행착오가 코드 견본과 `references/why.md`에 들어 있다.

메인 세션에서 돈다(fork 아님) — 사람 몫(저장소·토큰·Vercel·실기기 확인)이 여러 번 끼어 사용자와 말을 주고받아야 해서다.

| 문서 | 언제 읽나 |
|---|---|
| `references/adapters.md` | 단계 1 — 프로젝트마다 바꾸는 자리 표 |
| `references/human-setup.md` | 단계 2·5·끄기 — 사람 몫(화면·칸·버튼 이름), 테스터 안내, 실패 진단 |
| `references/code/*.md` | 단계 3·전환 — 코드 견본(파일 하나당 md 하나) + `wiring.md`(흩어진 한두 줄) |
| `references/why.md` | 사용자가 이유를 물을 때, 「바꾸지 않는 것」을 바꾸자는 말이 나올 때, 다른 스택으로 옮길 때 |

## 1. 두 방식

|  | 로그인 없는 방식 (`anon`) | 로그인 방식 (`auth`) |
|---|---|---|
| 언제 | idea-to-mvp 5단계 — Vercel 주소가 처음 생기고 피드백이 가장 필요한 때. 로그인·DB 없음 | 6단계 이후 — 로그인이 붙은 뒤(참고 구현과 같음) |
| 필요한 것 | GitHub 저장소 + Vercel 배포 | 위 + 프로젝트의 인증 |
| 누가 보내나 | 링크를 연 누구나 — **주소가 곧 공개 범위** | 로그인한 사람만 |
| 남발 막기 | 접속 IP 기준 30초 1번·하루 20번(IP는 해시로만, 로그·이슈엔 안 남김) | 계정 기준 30초 1번·하루 20번 |
| 이슈의 사람 정보 | 「보낸 사람: 로그인 없는 방식」 — 테스터에게 글 앞에 이름을 부탁 | 계정 id · 팀 · 팀에서 부르는 이름 |

- **갈리는 자리는 파일 두 개뿐이다** — 서버 `src/lib/qa-feedback/reporter.ts`(누구인가)와 화면 `src/lib/qa-feedback/gate.ts`(감지를 켜도 되나). 견본이 방식마다 한 벌씩 있고(`code/reporter.anon.ts.md`·`reporter.auth.ts.md`·`gate.anon.ts.md`·`gate.auth.ts.md`), 고른 방식의 것을 그 경로에 놓는다. 나머지 파일은 두 방식이 같다.
- **방식은 파일로 정한다. 환경변수로 고르지 않는다** — 로그인 방식 코드는 인증 모듈을 import해서 인증 없는 프로젝트에선 빌드가 깨지고, 환경변수 하나로 실서비스가 조용히 「누구나 보내기」로 바뀔 수 있어서다. 두 파일의 `QA_REPORTER_MODE`가 지금 방식이다. **둘이 다르면 반만 바꾼 고장이다 — 멈추고 보고한다.**
- 두 방식 모두: 스위치 `QA_FEEDBACK`, 같은 출처 검사, 크기·길이 한도, 이슈 본문 안전 처리, 주소 속 비밀값 가리기, 캡처 비공개 저장소, 토큰 둘 분리, 로그 금지 항목이 똑같이 걸린다.

## 2. 공통 규칙

- **시작 전 브랜치 확인** — `git branch --show-current`. main이면 `/new-task`로 작업 브랜치를 연 뒤 진행한다.
- **역할 표시** — 단계마다 [AI] / [사람]. **사람 몫은 한 번에 한 단계**만 화면·버튼 이름 그대로 안내하고 멈춘다. "됐습니다"를 받으면 [AI]가 그 단계를 확인한 뒤 다음으로 간다(github-connect와 같은 방식).
- **재실행 안전** — 단계마다 「이미 됐나」를 먼저 본다(폴더·라벨·저장소·환경변수 이름). 됐으면 건너뛰고, 마무리 보고에 한 일·건너뛴 일을 나눈다.
- **비밀값** — 사람 몫 시작 **전에** 「토큰 값은 대화창에 붙여 넣지 마세요」를 말한다. 설정 화면 캡처를 부탁할 때는 **먼저** 「키·토큰·시크릿이 보이면 가리고 올려 주세요」를 말한다(`human-setup.md` 1). 코드·장부·문서 어디에도 값을 적지 않고 환경변수 이름만 쓴다. 토큰 값을 화면에 출력하지 않는다.
- **gh 호출** — 프로젝트 `.env.cli` 토큰 로더 한 줄로 부른다: `env GH_TOKEN="$(sed -n 's/^GH_TOKEN=//p' .env.cli 2>/dev/null)" gh <명령>`. 전역 계정 전환(`gh auth switch`)은 쓰지 않는다.
- **실패 한도** — `docs/account-check.md` 원칙 ⑥: 같은 실패 2회면 멈추고 보고, 401·403·404는 재시도하지 않고 원인을 바꾼다.
- **바꾸지 않는 것** — 3번 터치 판정값, `capture.ts`의 아이폰 대응, 서버 확인 순서, 크기 한도, 이슈 본문 안전 처리, 로그 금지 항목, 토큰 둘 분리는 어댑터가 아니다(`adapters.md` 2절). 바꾸자는 말이 나오면 `why.md`의 근거를 보여 주고 사용자에게 묻는다.
- **화면 검증은 사람 몫** — 감지·캡처·창이 제대로 되는지는 사람이 실기기로 본다. AI는 빌드·린트·타입·단위 시험, 서버 로그, `gh`로 이슈 모양까지만 확인한다. 캡처 그림을 AI가 보고 「잘 찍혔다」고 판정하지 않는다.
- **말투** — 사용자에게 하는 보고·안내는 ~입니다 체로 쓴다. 서비스 화면 문구는 이 스킬이 정하지 않는다 — 프로젝트 `mvp/design-brief.md`의 보이스 앤 톤으로 초안을 쓰고 사람이 확정한다.

## 4. 새로 깔기

### 4.0 시작

[AI] 무엇을 까는지 세 줄로 알린다(~입니다 체):

1. 화면 빈 곳을 3번 연속 터치하면 한 줄 창이 뜨고, 보내면 GitHub 이슈가 생깁니다.
2. 함께 가는 화면 사진은 진짜 스크린샷이 아니라 화면을 다시 그린 그림이라, 실제 화면과 조금 다를 수 있습니다(웹은 휴대폰 화면을 직접 찍을 수 없습니다).
3. GitHub API로는 이슈에 그림을 바로 붙일 수 없어서, 사진은 따로 만든 **비공개 캡처 저장소**에 쌓고 이슈에서 그 그림을 불러옵니다. 캡처 저장소 권한이 있는 사람만 봅니다.

### 4.1 적용 전 확인 + 방식 고르기

[AI] 아래를 코드·설정에서 직접 찾아 `adapters.md` 표를 채운다. 못 찾은 것만 사용자에게 묻는다.

1. **스택** — Next.js App Router(`src/app` 또는 `app`)인가, Vercel에 배포되나(`.vercel/project.json` 또는 사용자 확인), 배포 주소가 이미 있나. **App Router나 Vercel이 아니면 깔지 않고 멈춰 보고한다** — 서버 주소·스위치·배포 정보·IP 머리글·요청 본문 한도(4.5MB 전제)를 다시 짜야 하는 일이라 이 스킬 범위 밖이다.
2. **로그인이 있나 → 방식 고르기** — 서버 쪽 로그인 코드(`src/lib/supabase/server.ts`·`auth.getClaims`·`auth.getUser` 등)나 `mvp/backend-build.md`가 있으면 로그인 방식, 없으면 로그인 없는 방식을 **추천**하고 사용자가 고른다. 로그인이 있어도 「로그인 전 화면에서도 받고 싶다」면 로그인 없는 방식을 고를 수 있다 — 이유를 `docs/qa-feedback.md`에 남긴다.
3. (auth) 서버·화면 로그인 확인 방식, 탈퇴 표시 칸, 팀(워크스페이스) 개념 — `auth-server`·`auth-client`·`team?`.
4. 공통 layout 자리(`mount`), 토스트(`toast`), 디자인 시스템 부품(`ui-sheet`·`ui-open-guard`·`overlay-selector`·`exclude-selectors`) — 화면 부품을 고르는 일이라 design-system 스킬의 adapter(프로젝트 `AGENTS.md` 「디자인 시스템 연결 정보」)를 메인이 읽고, 토큰 규칙 중 이 창에 닿는 것(임의 값 금지·하단 안전 영역 등)을 위임 지시서에 몇 줄로 넣는다.
5. 문구 모음 자리와 보이스 앤 톤(`copy` — `mvp/design-brief.md`).
6. 처리방침 자리 — 없으면 `code/wiring.md` 8절 끝(창 안내 + 테스터 안내로 대신하고 6단계에서 넣기).
7. 주소 속 비밀값(`mask-rules`) — 초대·재설정·공유 링크의 코드, 로그인 콜백 `code`.
8. **GitHub** — 코드 저장소(`git remote get-url origin`), 주인이 조직인가(`gh api repos/<저장소> --jq .owner.type`), 조직이면 작업 계정의 역할(`gh api orgs/<조직>/memberships/<계정> --jq .role` — `admin`이 아니면 토큰에 조직 소유자 승인이 필요), 비공개인가. 프로젝트 `AGENTS.md` 「소유와 계정」 표의 GitHub 계정과 지금 gh 계정(`gh api user --jq .login`)이 같은가.
9. Node 판(`node --version` — 단위 시험에 22.18 이상), middleware/proxy matcher, 전역 CSS 위치.

**멈춤 ①** — 사용자에게 보여 주고 확인받는다(~입니다 체): 고른 방식과 이유, 채운 어댑터 표(바꿀 자리만 짧게), 정할 이름 셋(캡처 저장소 이름 — 기본 `<프로젝트>-qa-shots`, 라벨 — 기본 `qa`, 켤 환경 — 기본 Preview, Production은 4.5에서), 조직 승인이 필요한지.

### 4.2 사람 몫 준비

`human-setup.md`를 순서대로, 한 단계씩. 각 단계 뒤 [AI]가 확인한다(저장소·라벨은 gh로, 환경변수는 `vercel env ls`로 **이름만**).

1. 경고 두 개(1절) → 계정 대조(2절).
2. 캡처 저장소(3절) — **AI가 `gh repo create`로 대신할지 먼저 묻는다.**
3. `qa` 라벨(4절) — **AI가 `gh label create`로 대신할지 먼저 묻는다.**
4. 토큰 두 개 발급(5.1절 칸별 표) → 조직 + member면 승인 요청(5.2절 견본). **승인은 몇 시간~며칠 걸릴 수 있으니 여기서 시작만 하고, 기다리는 동안 4.3·4.4를 진행한다.** 토큰 이름·만료일만 받아 둔다(값은 받지 않는다).
5. 배포 보호 확인(6.1절) — 테스터가 어느 주소로 들어올지 정한다.
6. 환경변수(6.2절) — **지금은 비밀 아닌 설정값만**(`QA_FEEDBACK=on`, `GITHUB_QA_REPO`, `GITHUB_QA_SHOTS_REPO`, 필요하면 `GITHUB_QA_LABEL`)을 Preview에. 사람이 넣거나, 사용자에게 묻고 AI가 `vercel env add`로 넣는다(Vercel CLI 토큰이 없거나 실패 2회면 사람 몫). **토큰 두 개는 4.5 직전에 넣는다** — 1차 실측은 토큰 없이(이슈 대신 로그만) 돈다.
7. (anon) 테스터 안내 견본(8절)을 사용자에게 준다 — 링크를 보내기 전에 함께 보낸다.

### 4.3 코드 깔기

하네스 위임 규칙대로 **서브 에이전트(general-purpose, sonnet — 명세가 분명한 코딩)에게 맡기고** 사용자에게 어떤 에이전트·모델인지 알린다. 견본은 「규칙 자료」가 아니라 「놓을 내용」이라, 메인이 읽어 붙여 넣지 않고 **견본 파일 경로를 넘겨 에이전트가 직접 읽게** 한다. 규칙(바꾸지 않는 것·어댑터 값·디자인 토큰 제약)은 메인이 지시서에 적는다.

지시서 골자:


### 4.4 1차 실측 — 감지·캡처

미리보기 배포가 필요하다 — 작업 브랜치를 push해 미리보기를 만들지 사용자에게 묻고(`auto-wip-commit` 훅이 커밋해 둔 것을 push), 만들어진 미리보기 주소를 알려 준다. 이때는 토큰이 없어 **이슈 대신 서버 로그 「이렇게 만들 뻔했어요」만** 남는다. 미리보기 주소에 Vercel 로그인 보호가 걸려 있으면 만드는 사람이 로그인된 브라우저로 연다.

[사람] 아이폰과 PC에서 확인해 달라고 한 줄씩 안내한다:

- 빈 곳을 빠르게 세 번 → 한 줄 창이 뜬다 / 글자·버튼·그림 위에선 안 뜨고 원래 동작(글자 선택·누르기·그림 메뉴)이 된다
- 아이폰에서 두 번 톡 확대가 일어나지 않는다 / 두 손가락 확대는 된다
- 창이 뜨자마자 닫히지 않는다 / 입력칸에 바로 쓸 수 있다(아이폰 자판이 안 올라오면 한 번 누르면 되는지)
- 보내기 → 성공 알림. 바로 다시 보내면 「조금 뒤에」 줄
- (auth) 로그아웃 상태에선 세 번 눌러도 안 뜬다
- (실측 필요 항목) 카톡 안 브라우저·안드로이드 크롬도 되면 같이

[AI] 서버 로그에서 `[qa-feedback] 이슈를 만들 뻔했어요` 줄을 찾아 `mode`·`shot.bytes`(캡처 크기)·`viewport`만 보고한다. 창이 아예 안 뜨면 `QA_FEEDBACK`이 빌드에 들어갔는지부터 본다(넣은 뒤 다시 배포했나, Config 타입 — `human-setup.md` 6.2).

**멈춤 ④** — 사람이 "됐습니다". 실측 결과를 `docs/qa-feedback.md`에 적는다.

### 4.5 2차 실측 — GitHub 연결, 그리고 보내기

1. **멈춤 ⑤** — 토큰 두 개가 발급·(필요하면) 승인됐는지 묻고, `human-setup.md` 6.2대로 Preview에 Secret으로 넣고 다시 배포한다. 아직 승인 대기면 여기서 기다린다.
2. [사람] 아이폰에서 **「스크롤 안 함 / 중간까지 스크롤 / 맨 아래」 화면에서 각각 한 번**, PC에서 한 번 보낸다(sticky 헤더·탭바가 있는 화면이면 그 화면에서). 로그인 없는 방식이면 테스터가 들어올 주소(6.1절에서 정한 것)로도 한 번.
3. [AI] `gh issue list --repo <코드 저장소> --label <라벨> --limit 10`으로 이슈 4개가 생겼는지, 라벨이 붙었는지, 본문에 표·기계용 묶음(`qa-meta`의 `mode`)이 있는지 본다. (anon) 본문 어디에도 IP가 없는지 본다. 서버 로그의 `label` 값도 본다.
4. [사람] 이슈를 **GitHub 웹과 GitHub 모바일 앱**에서 열어 그림이 보이는지, 캡처를 내려받아 위 헤더·아래 탭바가 제자리에 있는지, 아래쪽이 검거나 왼쪽에 검은 띠가 없는지, 고리 모양 테두리가 어긋나지 않는지, 창·토스트가 찍히지 않았는지 본다. **멈춤 ⑥**
5. **실패하면** — 화면 문구보다 **서버 로그 먼저**(실패한 제출도 30초 한도에 세서 「조금 뒤에」가 원인을 가린다). GitHub 404면 **토큰 승인 대기(Pending) 먼저**. 표는 `human-setup.md` 9절.
6. 통과하면:
   - `/security-review` — 업로드·공개 주소(·auth면 로그인 코드)가 걸린 브랜치다. 지적을 처리한다.
   - 처리방침 문구가 들어갔는지(또는 「남은 일」에 적혔는지) 확인.
   - **Production에도 켤지** 묻는다 — 로그인 없는 방식은 테스터가 실서비스 주소로 들어오는 경우가 많아 보통 켠다(정식 공개 전 `QA_FEEDBACK` 삭제로 끈다). 켜면 Production에 `QA_FEEDBACK`·저장소 이름·토큰을 넣고, 머지 뒤 배포에서 반영된다.
   - 실측 결과를 `docs/qa-feedback.md`에 적고, "화면 확인하셨으면 보낼까요?"라고 묻는다 → 사용자가 "보내줘"라고 하면 `/done-task`.

## 5. 끄기

## 6. 로그인 방식으로 전환

`anon`으로 깔았는데 로그인이 붙었을 때. 환경변수·토큰·GitHub 저장소·라벨은 **바꾸지 않는다** — 같은 스위치·같은 토큰 둘·같은 저장소를 쓴다.

| 3 | 나머지 qa-feedback 파일·라우트·컴포넌트 | **바꾸지 않는다** — 두 방식 공통 | — |
