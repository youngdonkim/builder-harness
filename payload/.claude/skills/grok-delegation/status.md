## 미해결 이슈
- 정식 T1~T3 테스트가 스크래치 디렉토리에서 실행되지 않았다. delegation-integrator로 한 번 돌려야 한다.
- **병렬 출력 섞임 — CLI 1.0.5 + 표식 처방으로 사실상 해소 (2026-08-19 실측 4회, 상세는 reference.md 연대기).** 1.0.3은 최종 보고까지 글자 단위로 섞였고(섹션 5개 중 1개만 온전), 1.0.5는 진행 스트림만 섞이고 **최종 보고 블록은 온전**하다(plain·json 양쪽 확인). 표식 처방(지시서에 `=====REPORT=====` 요구 + 문자열 검색으로 뒤만 읽기)과 조합해 병렬을 조건부 허용으로 SKILL.md에 반영했다. 남은 위험 둘: ① 공유 파일 동시 갱신은 1회 실측 통과뿐(확률 위험 — 파일 단위 분담을 권장으로 반영) ② 진행 스트림 섞임 자체는 여전하나 버리는 부분이라 무해.
  - 2026-08-19 조사 결과 (원인 위치): 섞임은 **grok 자체의 `--output-format plain` 스트림**에서 난다. 브리지는 grok 프로세스 하나의 stdout을 통으로 누적할 뿐이고(`lib/grok.mjs`의 `stdout += chunk`), plain 텍스트엔 에이전트 태그가 없어 브리지에서 복원 불가. 브리지 `run`은 plain이 하드코딩(`grok-bridge.mjs`의 `outputFormat: "plain"`)이라 밖에서 못 바꾼다.
  - 후보 해결책 (조사 시점 기록 — ①은 이후 검증돼 채택, ②는 검증 결과 경계 문제를 못 풀어 불채택, ③④는 표식 처방 확립으로 불필요해짐): ① CLI 1.0.5 업데이트 후 재현 (1.0.4에 "Subagent lifecycle events stay correct even when delivered out of order" 수정 있음 — 다만 stdout 텍스트 섞임 수정이라는 명시는 없음), ② 브리지 우회 직접 호출 `grok -p ... --output-format json` (최종 JSON 한 덩어리만 받아 중간 스트림 섞임 회피), ③ `grok -p ... --no-subagents` (서브 에이전트 원천 차단 — 병렬성 포기), ④ `--output-format streaming-json` (NDJSON 이벤트 단위라 글자 섞임은 구조상 없음 — 이벤트에 에이전트 식별자가 붙는지는 공식 문서에 없어 실행 검증 필요). 플러그인 0.2.1은 업스트림 최신이고 관련 수정·이슈 없음.
- **`--resume`이 실패해도 종료 코드가 0으로 나온다.** 브리지 쪽 문제인지 그록 CLI 쪽인지 아직 안 밝혔다. 지금은 `git status`로 파일 변경 여부를 직접 확인하는 것으로 우회하고 있다. delegation-integrator가 원인을 확인하고, 고칠 수 있는 자리인지(하네스인지 플러그인인지) 판단해야 한다.
