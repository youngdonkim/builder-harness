# harness-diet — 지시 문서 다이어트

지시 문서(AI가 읽고 따르는 규칙 문서)는 쓸수록 불어난다. 이 스킬은 그 문서들을 회차로 쪼개 정독시키고, 군살·중복·죽은 참조·모순을 찾아 **보고서 하나**로 모은 뒤, 사람이 정해야 할 것을 물어보는 데까지 한다. **여기까지가 범위다.** 실제 수정은 사용자가 항목을 고른 뒤 **별도 지시**로 진행한다 — 큰 일은 「검토」와 「구현」으로 두 번 나눠 맡기는 원칙 그대로다. 한 번에 검토하고 고치게 하면 되돌리기가 어렵다.

**이 검토의 실패 모드는 "덜 지움"이 아니라 "지우면 안 될 걸 지움"이다.** 실측 값·사고 사례·명령문은 애초에 삭제 후보가 아니다. 애매하면 항목에서 빼고 "확신 없어 뺀 것"에 남긴다.

**시작 전 브랜치 확인** — 파일을 바꾸기 전에 지금 어느 브랜치인지 먼저 본다.

```bash
git rev-parse --abbrev-ref HEAD
```

**main이면 `/new-task`를 직접 호출해 작업 브랜치를 연 뒤 진행한다.** main에서 파일을 바꾸면 `auto-wip-commit` 훅이 안 돌아 자동 저장이 안 되고(되돌릴 지점이 안 남는다), 나중에 `no-main-push` 훅에 막혀 올리지도 못한다.

## 1. 모드 판별

저장소 루트를 보고 둘 중 하나로 정한다.

- **`payload/`가 있으면 → 하네스 원본 모드.** 검토 대상은 `payload/` 전체 + 루트 `CLAUDE.md`·`AGENTS.md`·`README.md`다. 발견한 항목은 **이 저장소에서 바로 고칠 수 있다**(수정은 결정 후 별도 지시).
- **`.claude/harness-version`이 있으면 → 프로젝트 모드.** 하네스 소유 파일(payload 미러로 복사돼 온 것 전부)은 **여기서 고치면 안 된다** — 다음 동기화가 덮어쓴다(`project-init` 참조). 검토는 하되 발견 항목을 두 갈래로 나눈다:
  - ① **프로젝트 고유 내용** — CLAUDE.md·AGENTS.md에서 이 프로젝트가 채워 넣은 부분, 프로젝트가 스스로 추가한 규칙·문서 → 이 저장소에서 수정 후보.
  - ② **하네스 소유 파일의 문제** → 항목 앞에 **`[하네스 제안]`**을 붙여 보고서에 모으고, "이건 builder-harness 저장소에 반영해야 한다"고 안내한다.

## 2. 회차 설계

### 대상을 층으로 나눈다

- **상시 로드층** — `CLAUDE.md`·`AGENTS.md`와 그 템플릿. 매 세션 무조건 읽힌다.
- **발동 시 로드층** — 스킬의 `SKILL.md`, `agents/`, `rules/`. 그 스킬·에이전트가 발동할 때만 읽힌다.
- **참조층** — `references/`와 부속 파일. 그 단계에 들어갔을 때만 읽힌다.

층을 가르는 이유는 **한 줄의 값이 층마다 다르기 때문**이다. 상시 로드층 한 줄은 매 세션 비용이라 복리로 붙고, 참조층 한 줄은 그 단계에서만 든다. 그래서 같은 문장이라도 어느 층에 있느냐로 처방이 갈린다.

### 분량을 재고 회차를 나눈다

```bash
wc -l <대상 파일들>
```

- 한 회차 **2,000줄 안팎**으로 묶는다. 큰 층은 더 쪼갠다.
- 이렇게 쪼개는 이유: 한 번에 다 읽히면 **뒤쪽 파일 판정이 대충 나온다.** 앞부분만 꼼꼼하고 뒤로 갈수록 "문제 없음"이 늘어나면 그건 다 읽은 게 아니라 지친 것이다.

### 기준 문서는 매 회차에 함께 읽힌다

**상시 로드층 전부**를 모든 회차의 기준 문서로 넣는다. 이번 회차 파일이 기준 문서와 **겹치면 B**, **어긋나면 [모순]**으로 잡힌다. 기준 없이 층을 따로 보면 층 간 문제가 통째로 사각지대가 된다.

## 3. 병렬 감사

회차마다 `harness-auditor` 에이전트를 **층 감사 모드**로 하나씩 띄운다. 회차가 여럿이면 한꺼번에 띄운다 — 메인이 여러 에이전트를 동시에 띄우는 건 재위임이 아니라 정상이다.

호출 프롬프트에 반드시 담을 것:

1. **모드** — "층 감사 모드"
2. **정독할 파일 목록** — 경로를 **빠짐없이** 나열한다. "이 폴더 전부" 같은 말로 넘기지 않는다. 목록에 없으면 안 읽는다.
3. **기준 문서 목록** — 상시 로드층 파일 경로.
4. **반환 형식** — 에이전트 본문에 정의된 형식 그대로 (요약 → 파일별 항목 → 확신 없어 뺀 것 → 사람이 정해야 할 것 → 규칙 인덱스).

## 4. 검수와 조립

회차 결과가 오면 **메인이 직접 검수한다.** 대충한 신호 세 가지:

- **원문 인용이 없다** — 위치를 줄 번호로만 적었으면 안 읽고 지어냈을 가능성이 크다.
- **C·D에 grep 근거가 없다** — 죽은 참조·낡은 사실은 확인 명령 결과가 붙어야 한다.
- **큰 파일에서 항목이 0개인데 "확신 없어 뺀 것"에도 안 보인다** — 정말 깨끗한 게 아니라 안 읽은 것이다.

하나라도 걸리면 **그 회차만 다시 돌린다.** 통과하면 `docs/harness-diet-review.md`에 조립한다.

- **기존 파일이 있으면 덮어쓴다.** 옛 보고서는 git 이력에 남으니 `-v2` 같은 이름을 만들지 않는다.
- 머리에 **작성일 · 브랜치 · 회차 구성 · 판정 분류 범례**를 적는다.

## 5. 교차 검토

조립이 끝나면 `harness-auditor`를 **교차 검토 모드**로 한 번 더 띄운다. 이번엔 **보고서 파일 하나만** 읽힌다 — 원문은 안 연다.

결과(층 간 중복, 층 간 모순 후보, 서로 안 가리키는 흩어짐, 사람 결정 통합 목록)를 보고서 **끝에 회차로 붙인다.**

## 6. 마무리 — 사람 결정

- 회차마다 나온 "사람이 정해야 할 것"을 **하나의 우선순위 목록**으로 합친다.
- **결정 하나가 여러 항목을 푸는 순서**로 배열한다 — 층 배치 기준 같은 큰 결정을 먼저 물으면 그 아래 항목들이 한꺼번에 정리된다.
- 각 결정에 "이걸 정하면 풀리는 항목"과 추천안을 붙여 사용자와 상의한다.

**여기서 스킬이 끝난다.** 수정은 사용자가 항목을 고른 뒤 별도로 지시받아 진행한다. 그때 지킬 철칙 세 개를 안내에 남긴다:

1. **실측·사고 원문 유실 0** — 이동(G)은 삭제가 아니다. 이동 전후 diff를 대조해 원문이 한 글자도 안 사라졌는지 확인한다.
2. **미러 동기화** — `payload/.claude/`를 고쳤으면 루트 `.claude/`에 같은 파일을 복사한다.
3. **수정 후 잔재 grep** — 지운 이름·경로가 다른 문서에 남아 있지 않은지 grep으로 확인한다. 한쪽만 고치면 죽은 참조가 새로 생긴다.

## 안 하는 것 (의도적)

- ❌ **보고서 말고 다른 파일을 만들거나 고치지 않는다** — 이건 검토 스킬이다.
- ❌ **발견 항목을 자동으로 고치지 않는다** — 결정은 사람 몫이다.
- ❌ **B·C로 분류된 행동 규칙·실측 문장을 "다듬자"고 제안하지 않는다** — 다듬다 사고 맥락이 날아가는 게 지시 문서가 나빠지는 제일 흔한 경로다.
- ❌ **프로젝트 모드에서 하네스 소유 파일을 고치지 않는다** — `[하네스 제안]`으로 모아서 넘긴다.
