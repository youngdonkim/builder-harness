# 계정 명부

프로젝트 소유(개인/회사)별로 **어느 계정으로 외부 서비스를 만드는지** 적어 둔 명부다. `/project-init`이 소유 답을 받으면 여기서 그 세트를 읽어 프로젝트 `AGENTS.md`의 「소유와 계정」 표를 채운다. 값 자체(비밀번호·키·시크릿)는 절대 여기 적지 않는다 — 계정 이름과 이메일뿐이다.

이 파일은 `payload/` 바깥이라 프로젝트에 복사되지 않는다. 프로젝트에는 자기 소유자의 세트만 들어간다.

**성격: 하네스 사용자가 자기 계정으로 직접 채우는 데이터 파일이다** — 템플릿(placeholder 채워 프로젝트로 복사되는 것)도, 그냥 참고 문서도 아니다. 하네스는 여러 사람이 쓰는 범용이라 **이 저장소에는 누구의 실제 계정도 미리 적혀 있지 않다** — 각자 자기 clone에서 아래 `(입력)` 칸을 채워 쓴다. AI는 `project-init`(표 채울 때)과 idea-to-mvp `6-0-backend-prep.md`(계정 대조·확정 문안 만들 때)가 경로를 콕 집어 지시하는 시점에 읽는다. docs/에 있어서 매 세션 자동 로드되지는 않지만, 스킬이 명시 경로로 읽으니 필요한 순간엔 반드시 열린다.

## 채우는 법

- **첫 프로젝트를 시작하기 전에 미리 채워 둔다.** 안 채워 두면 project-init이 프로젝트마다 계정을 새로 묻게 되고, 잘못 로그인된 계정으로 리소스가 만들어지는 사고(6-0 실사고)를 명부가 막아 주지 못한다.
- **개인/회사를 구분할 필요가 없으면**(모든 프로젝트를 같은 계정으로 만들면) **「개인」 표만 채운다.** 회사 표는 `(입력)` 그대로 두면 되고, project-init의 소유 질문에는 늘 "개인"으로 답하면 된다.
- 아직 확실하지 않은 칸은 `(확인 필요)`로 바꿔 두면 된다 — 6단계 준비(6-0)에서 실제 계정이 확정될 때 채우라는 문안이 돌아온다.

## 계정 인증 다루는 법 — 로그인 세션과 발급 토큰

CLI 인증은 두 종류다. **로그인 세션**은 `login` 류 명령이 만드는 것 — 컴퓨터당 하나만 남고, 서비스가 정한 기간이나 "오래 안 쓰면 회수" 규칙으로 만료된다(영구가 아니다). **발급 토큰**은 계정 화면에서 손으로 만드는 접근 토큰 — 수명을 고를 수 있고 무기한도 되며, 여러 개가 공존한다. 무기한이어도 장기간 안 쓰면 회수하는 서비스가 있으니, 안 되면 재발급이 정답이다.

**소유가 다른 프로젝트가 한 컴퓨터에 있으면 로그인으로 갈아타지 않는다** — 계정마다 발급 토큰을 만들어 각 프로젝트에 두고, CLI가 그 토큰을 읽게 한다. 로그인 전환은 전역이라 다른 프로젝트를 조용히 망가뜨린다. 예외는 여러 계정을 등록해 두고 전환하는 CLI(gh 같은 Git 호스팅 CLI) — 프로젝트에 들어갈 때 활성 계정을 표와 맞춘 뒤 진행한다(로컬 전환이라 되돌리기 쉽다). 인공지능 제공사 키는 로그인이 아니라 API 키라 기존 규칙 그대로다. **발급 토큰은 소유 계정당 하나가 기본이고, 그 소유의 프로젝트들이 사본을 나눠 갖는다** — 프로젝트 폴더에는 그 프로젝트 소유 계정의 토큰만 두고, 더 좁혀야 하면 서비스가 지원하는 프로젝트 스코프 토큰을 따로 만든다. **손으로 넣은 로컬 값은 도구가 덮어쓰거나 앱이 읽는 파일에 두지 않는다** — 배포 CLI의 환경변수 내려받기는 기본 대상 파일을 통째로 다시 쓴다(실측). CLI 토큰은 프레임워크가 실행 시 읽지 않고 내려받기가 건드리지 않는 깃 미추적 **CLI 전용 파일**(예: `.env.cli`)에 두어 명령을 부를 때만 읽어 넘기고, 그 밖에 손으로 넣은 값(DB 비밀번호 등)도 내려받기 전에 따로 보관돼 있는지 확인한다.

- **gh** — 전환형이다. 계정을 여러 개 등록해 두고 전환한다(방법은 CLI 도움말). 프로젝트를 옮겨 다닐 때마다 활성 계정을 표와 맞춘다 — 전환은 전역이라 다른 소유의 프로젝트를 오간 뒤 특히.
- **GitHub SSH 키** — 키 하나는 한 계정에만 등록된다. 소유가 다른 저장소가 한 컴퓨터에 있으면 계정별 키를 따로 두고, ssh 설정의 호스트 별칭으로 저장소 원격 주소에 어느 키를 쓸지 박아 둔다 — 별칭 규약: `github.com-<소유자 태그>`. 설정 방법은 그때 공식 문서로. (실사고: 개인 키로 회사 저장소 push 거부 — 키를 옮기면 반대쪽이 막힌다.)
- **Vercel** — CLI 인증은 발급 토큰으로 한다(로그인 갈아타기 금지 — 위 원칙). 프로젝트 폴더의 `.vercel/project.json`이 어느 팀(orgId)에 묶였는지가 정본이다. 대시보드에서 계정을 바꿀 땐: **다른 계정 세션이 살아 있는 채로 GitHub/Google 로그인을 누르면 "로그인"이 아니라 "현재 계정에 그 로그인 수단 연결"이 된다** — 로그아웃이 실제로 됐는지(로그인 폼이 뜨는지) 확인한 뒤 로그인한다. (실사고: 회사 Vercel 계정에 개인 GitHub이 연결돼 끊어야 했다.) 토큰은 CLI 전용 파일에 둔다(위 원칙).
- **Supabase** — CLI 인증은 발급 토큰으로 한다. 지금 어느 계정인지는 CLI 자체의 계정·조직 조회 명령으로 확인한다. 프로젝트 `supabase/.temp/project-ref`가 어느 조직 것인지가 정본.
- **맥 키체인** — 키체인에서 CLI 토큰을 꺼내는 조회 명령은 허용 창이 떠서 무한 대기한다(실측 여러 번). 계정 확인은 그 CLI 자체의 계정·조직 조회 명령으로 하고, 무한 대기 가능성이 있는 명령은 시간 상한을 걸어 부른다.
- **브라우저 콘솔(Google·카카오·Supabase 대시보드)** — 아이디가 아니라 **오른쪽 위 프로필의 이메일**로 판단한다. 여러 계정이 동시에 로그인돼 있으면 마지막에 쓴 계정이 기본으로 열린다 — 콘솔 주소의 `authuser=` 값이나 프로필 전환으로 바꾼다.
- **브라우저 세션·2FA(2단계 인증)** — 브라우저 로그인 세션은 영구 보장이 없다. 프로필을 소유별로 나눠도 오래 안 쓴 프로필은 다시 로그인이 필요할 수 있다 — 프로필 분리는 재로그인 확률을 낮추는 수단이지 보장이 아니다. **2FA가 켜진 계정은 에이전트가 혼자 전환하지 못한다** — 로그인 화면에서 멈춰 사람에게 코드·패스키를 부탁한다. 복구 코드는 쓸 때마다 사라지는 소모품이라 상시 수단이 아니다. 손 갈 일을 줄이는 순서: CLI는 발급 토큰으로 로그인 자체를 없애고, 남는 브라우저 작업은 에이전트가 쓰는 컴퓨터에 패스키를 등록해 한 번의 승인으로 줄인다.
- **Aside(브라우저 에이전트)** — 프로필을 소유자별로 가를 수도 있고, 한 프로필에 여러 소유자 계정을 같이 둘 수도 있다. 어느 쪽이든 브라우저 작업은 프로필이 아니라 **표의 계정을 지정·대조한다** — 여러 계정을 지원하는 서비스(구글·GitHub)는 계정을 지정해 열고, 한 번에 하나만 되는 서비스(Vercel·Supabase 등)는 로그인된 계정을 표와 대조해 다르면 전환한 뒤 진행한다. 연결(연동 로그인·앱 설치·저장소 연결)은 **양쪽 서비스를 본다** — 상대 서비스(로그인·권한을 빌려주는 쪽)의 로그인 계정도 표와 대조한 뒤 진행한다. 비밀번호는 Aside의 암호화 금고가 저장·자동 채움하니 명부·표에는 계정 ID·이메일만 둔다. 실측한 함정 일곱:
  - `aside account list`의 프로필(u0·u1…)은 **Aside에 로그인한 구글 계정 단위**다. 서비스(Vercel 등) 로그인은 프로필과 별개라, 프로필이 개인 구글이어도 그 안의 Vercel은 회사 계정일 수 있다 — 판정은 늘 서비스 화면의 계정 표시로 한다.
  - `aside repl`은 호출마다 사실상 새 문맥이다 — 앞 호출의 `page`·ref는 못 쓰고, 이전에 연 탭에 다시 붙는 것(`attachBrowserTab`)은 시간 초과가 잦다. 한 동작 묶음(열기 → 스냅샷 → 클릭 → 스냅샷)은 `openTab`으로 새 탭을 열어 **한 호출 안에서** 끝낸다. ref는 같은 호출 안의 스냅샷에서만 얻는다.
  - 로그아웃 확인은 로그인 폼이 스냅샷에 보이는 것으로 한다. 구글 로그인을 누르면 프로필에 든 구글 계정 전부가 선택 화면에 나오므로 이메일로 고른다.
  - 2FA 화면이 뜨면 거기서 멈춘다. 패스키 버튼은 사람이 컴퓨터 앞에 없거나 이 브라우저에 패스키가 없으면 아무 반응이 없다. 로그인 폼에 뜨는 Aside의 「Save credential」 창은 금고 저장 제안이라 무시해도 된다.
  - Aside는 사용자가 실제로 쓰는 브라우저다. 열려 있는 다른 탭을 닫거나 건드리지 않는다.
  - `aside repl`에는 파일 쓰기(`fs`)와 `getByPlaceholder` 같은 이름 로케이터가 없다 — CSS 로케이터(`page.locator('input[placeholder="…"]')`)와 `console.log` 출력만 쓴다. `openTab`으로 연 탭은 호출이 끝나면 닫혀서 다음 호출에서 다시 못 읽는다.
  - 한 번만 보여주는 값(발급 토큰 등)은 접근성 트리 스냅샷에 안 잡힌다 — 생성 직후 `page.evaluate(() => document.body.innerText)`에서 정규식으로 읽어 같은 호출 안에서 출력한다. 스코프처럼 다단계로 고르는 선택 UI는 마지막 단계까지 고른 값이 입력칸에 표시된 것을 스냅샷으로 확인한 뒤 만든다.
