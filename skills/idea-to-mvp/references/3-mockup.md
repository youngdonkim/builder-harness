## 1. 단계 목표

이 단계의 목표는 **`user-story.md`를 외부 Claude Design에 입력해 전체 화면 플로우의 standalone HTML(외부 파일 참조 없이 폰트·이미지·컴포넌트 소스까지 전부 내장된 자급자족 단일 파일) 목업을 만드는 것**이다. 산출물은 **프로젝트 루트**의 `[projectName]-proto.html` 하나(projectName = 프로젝트 폴더명, 항상 최신본 하나) — 이 목업이 4단계(DemoValidation) 데모 인터뷰의 도구이자 화면 영역의 SoT(Source of Truth — 진실의 원천) 시작점이다.

**AI는 안내·프롬프트 준비까지만 한다** — Claude Design 실행과 결과물 저장은 사용자 몫이다. Claude Design은 이 스킬 바깥의 외부 도구라 AI가 대신 호출·실행할 수 없다. 목표를 이뤘는지는 §3 완료 체크리스트로 판정한다.

## 2. 진행 절차

### 2.1 단계 시작 — 이전 정리 내용을 보여주고, 이번 단계가 할 일을 안내한다

이 단계부터는 이전 단계(UserStory)가 남긴 산출물이 있다. `mvp/user-story.md`를 읽고 **로그라인**(logline — 서비스의 정서를 담은 한 줄 요약)과 **확정 입력 5개**를 짧게 요약해 보여주는 것으로 시작한다. 2단계(MarketResearch)에서 조사 요약이 있으면 함께 짧게 보여준다 — 게이트는 아니지만, 거기서 본 경쟁 서비스 화면·빈틈이 이번 목업 방향(어떤 화면·기능에 힘을 줄지)을 잡을 때 참고가 된다.

그다음 **왜 화면 명세 문서 없이 곧장 목업으로 가는지**를 설명한다.

설명 골자 — 그대로 또는 풀어서 전달:

> 유저 스토리의 장면(S#)마다 붙어 있는 *[화면]* 지문이 이미 화면 스펙이야. 예전엔 이걸 다시 문서(화면 설계서)로 옮겨 적는 단계가 있었는데, AI 빌더 시대엔 목업 만드는 게 몇 분짜리 작업이라 그 문서를 한 번 더 유지하는 게 오히려 이중 비용이야. 그래서 유저 스토리 → 곧장 목업(Claude Design)으로 간다.

이미 프로젝트 루트에 `[projectName]-proto.html`이 있으면(스킬 중간 재실행 등) §3 체크리스트로 검증해 부족한 부분만 보완하도록 안내한다 — 처음부터 다시 만들지 않는다.

### 2.2 Claude Design 안내

목업 제작은 사용자가 외부 [Claude Design](https://support.claude.com/en/articles/14604416-get-started-with-claude-design)에서 직접 진행한다. AI(여기)는 그 호출에 들고 갈 것을 준비해 안내하는 것까지만 한다.

**① 모드 선택**

유저 스토리의 플랫폼 맥락을 보고 고른다:
- 모바일 앱이 중심이면 → **Mobile app design**
- 웹이 중심이면 → **UI mockups**
- 애매하면 사용자에게 확인.

(참고: 4단계 데모 검증 단계에선 링크 하나로 공유되는 웹 쪽이 공유 마찰이 적다.)

**② 입력**

`mvp/user-story.md` 전문을 그대로 복사해 Claude Design 대화창에 붙여넣는다.

**③ 권장 프롬프트**

```
첨부한 유저 스토리 문서의 장면(S#) 순서와 *[화면]* 지문을 그대로 따라 전체 화면 플로우를 만들어줘.
장면에 없는 화면·기능은 추가하지 마.
문서의 마이크로카피·버튼 문구를 그대로 사용해줘.
결과물은 standalone.html(외부 파일 참조 없이 폰트·이미지·컴포넌트 소스까지 전부 내장된 자급자족 단일 파일)로 내보내줘.
```

**④ 결과물 받기**

Claude Design이 완성하면 **standalone.html**로 다운로드하도록 안내한다 — 여러 파일로 쪼개진 산출물(별도 README·컴포넌트 폴더 등)은 받지 않는다.

### 2.3 저장 규칙

받은 standalone.html은 **프로젝트 루트**에 `[projectName]-proto.html`로 저장한다(`projectName`은 이 저장소 최상위 폴더 이름 그대로). 버전 폴더·zip 압축 해제·README를 만들지 않는다 — 항상 최신 하나만 존재. 갱신될 때도 같은 파일명으로 덮어쓴다.

### 2.4 순환 갱신 (4단계에서 복귀 시)

4단계(DemoValidation)의 데모 인터뷰에서 **구조적 수정사항**(플로우·화면 구성·핵심 기능이 바뀌어야 하는 피드백)이 나오면 이 단계로 되돌아온다. 절차:

1. AI가 3단계에서 정리된 구조적 수정사항을 **Claude Design용 반영 프롬프트**로 정리한다 — 무엇을 어떻게 바꿔야 하는지 구체적으로 (예: "3단계 화면을 2단계보다 앞으로 옮기고, 온보딩에서 카드 입력 단계를 없애줘 — 이유: 인터뷰이 다수가 그 단계에서 이탈").
2. 사용자가 그 프롬프트로 Claude Design을 재호출해 목업을 재생성한다.
3. 받은 standalone.html을 같은 파일명(`[projectName]-proto.html`)으로 교체한다.
4. 4단계로 복귀해 다음 라운드 데모를 진행한다.

4단계가 **수렴**(구조적 수정 0건 — 4-demo-validation.md §2.8) 판정을 내리면 이 파일을 **동결**한다 — 이후 더 이상 재생성하지 않는다. 동결된 이 파일이 5단계(MvpBuild)의 정답지가 된다.

## 3. 완료 체크리스트

- [ ] **모드 선택 확정** (§2.2①) — 모바일/웹, 애매하면 사용자 확인 완료.
- [ ] **`user-story.md` 전문 입력 + 권장 프롬프트로 Claude Design 호출** (§2.2②③)
- [ ] **standalone.html 수령** (§2.2④) — 여러 파일로 쪼개진 산출물이 아님.
- [ ] **프로젝트 루트에 `[projectName]-proto.html`로 저장** (§2.3)
- [ ] **브라우저로 열어 정상 실행 확인** (사용자 검증 — AI 자동 사인오프 아님)

### 3.1 다음 단계 핸드오프

산출물 저장 직후, 매 단계 공통대로 **`/clear` 후 `/idea-to-mvp` 재호출**을 권장한다 (SKILL.md §3.2). 다음 단계는 4단계(DemoValidation) — 이 목업을 들고 데모 인터뷰를 진행한다. 인터뷰 중 구조적 수정이 나오면 §2.4 순환으로 이 단계에 다시 돌아올 수 있다 — 수렴할 때까지 3↔4단계를 오간다.

## 4. 산출물 스펙

위치: **프로젝트 루트**의 `[projectName]-proto.html` 파일 하나. `mvp/`엔 이 단계 산출물이 없다.

- **파일명**: `[projectName]-proto.html` (`projectName` = 프로젝트 폴더명)
- **형태**: standalone.html — 폰트·이미지·컴포넌트 소스까지 전부 내장된 자급자족 단일 파일
- **버전 없음, 항상 최신 하나** — 버전 폴더·zip 압축 해제·README 없음
- **동결 시점**: 4단계가 수렴 판정을 내릴 때까지는 반복 갱신(같은 이름 덮어쓰기) 대상. 수렴 후엔 동결 — 5단계(MvpBuild)의 정답지로 넘어간다.

## 5. 사용자 응대 톤

- **톤**: SKILL.md §1.3 따름 — 반말·친근·짧게.
- **AI는 Claude Design을 대신 실행하지 않는다** — 프롬프트 준비·결과 저장 안내까지만. 사용자가 "네가 대신 만들어줘" 하면 외부 도구라 AI가 못 들어간다는 걸 짚어준다.
- **목업 품질 불만**: "화면이 별로다", "이상하게 나왔다" 하면 다시 만들어달라고만 던지지 말고, §2.2③ 프롬프트를 더 구체화(빠진 장면·지문 짚기)해서 재생성하자고 안내한다.
- **모드 선택 애매**: 억지로 정하지 말고 사용자에게 확인.
- **순환 중 재요청**: 4단계에서 돌아온 경우 §2.4 절차대로 반영 프롬프트부터 정리해 주고, 사용자가 그 프롬프트로 재호출하도록 안내한다 — AI가 임의로 목업 내용을 지어내지 않는다.
