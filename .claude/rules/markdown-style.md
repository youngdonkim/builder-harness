# 마크다운 목차(TOC) 작성 규칙

목차는 `## 목차` 헤더 아래 **앵커 링크를 건 번호 리스트**로 쓰고, 리스트 끝에 빈 줄 + `---` 구분선을 둔다.

- 최상위 절: `1. [제목](#앵커)` — 링크 텍스트에 번호를 다시 쓰지 않는다.
- 하위 절: 들여쓰기한 대시 리스트로, 점 번호를 링크 텍스트 앞에 붙인다 (`- [2.3 화면 명세](#23-화면-명세)`). 한 단계 더 깊어지면(예: 2.3.1) 들여쓰기도 그만큼 더.
- 앵커는 실제 헤더 텍스트에서 GitHub 슬러그 규칙으로 만든다 — 영문은 소문자로, 마침표·괄호·가운뎃점 같은 특수문자 제거, 공백은 `-`, 연속 하이픈은 합치지 않는다. 단 ①②처럼 숫자·글자 성격의 기호는 지우지 않는다 — 지우면 앵커가 실제 헤더와 어긋나 링크가 죽는다.

여러 하위 섹션을 `·`(가운뎃점) 같은 구분자로 한 줄에 나열하지 않는다 — 줄바꿈이 없어 구조가 한눈에 안 들어온다.

**나쁜 예**:
```
- §2 진행 절차 — §2.2 플로우 골격 · §2.3 화면 명세(7요소) · §2.4 시나리오 경로
```

**좋은 예**:
```
## 목차

1. [단계 목표](#1-단계-목표)
2. [진행 절차](#2-진행-절차)
   - [2.2 플로우 골격](#22-플로우-골격)
   - [2.3 화면 명세(7요소)](#23-화면-명세7요소)

---
```

**`§1`·`§2.3` 같은 절 번호는 본문 교차 참조 관례다** — 본문에서 다른 절을 텍스트로 가리킬 때 쓰는 이 저장소만의 표기이고, 목차에는 쓰지 않는다. 목차 항목 자체를 `#`·`##` 헤더 문법으로 쓰지도 않는다 — 같은 이름의 헤더가 중복돼 문서 아웃라인이 꼬인다.
