## 미해결 이슈
- 정식 T1~T3 테스트가 스크래치 디렉토리에서 실행되지 않았다. delegation-integrator로 한 번 돌려야 한다.
- **병렬 서브 에이전트 출력 섞임은 현존하는 버그다 (2026-08-19 재현 확인).** 병렬을 허용한 조사 지시로 재현 테스트한 결과, 그록이 서브 에이전트를 동시에 띄웠고 진행 메시지와 보고서 본문이 글자 단위로 뒤섞였다(요청한 섹션 5개 중 온전한 제목 1개). 종료 코드는 0이었다. 그록 CLI 쪽 문제라 우리가 못 고친다 — 지시서의 "병렬로 띄우지 마라" 문구로 우회 중이고, 이 규칙은 유지해야 한다.
  - 2026-08-19 조사 결과 (원인 위치): 섞임은 **grok 자체의 `--output-format plain` 스트림**에서 난다. 브리지는 grok 프로세스 하나의 stdout을 통으로 누적할 뿐이고(`lib/grok.mjs`의 `stdout += chunk`), plain 텍스트엔 에이전트 태그가 없어 브리지에서 복원 불가. 브리지 `run`은 plain이 하드코딩(`grok-bridge.mjs`의 `outputFormat: "plain"`)이라 밖에서 못 바꾼다.
  - 후보 해결책 (전부 쿼터 소모 테스트 전 = 미검증): ① CLI 1.0.5 업데이트 후 재현 (1.0.4에 "Subagent lifecycle events stay correct even when delivered out of order" 수정 있음 — 다만 stdout 텍스트 섞임 수정이라는 명시는 없음), ② 브리지 우회 직접 호출 `grok -p ... --output-format json` (최종 JSON 한 덩어리만 받아 중간 스트림 섞임 회피), ③ `grok -p ... --no-subagents` (서브 에이전트 원천 차단 — 병렬성 포기), ④ `--output-format streaming-json` (NDJSON 이벤트 단위라 글자 섞임은 구조상 없음 — 이벤트에 에이전트 식별자가 붙는지는 공식 문서에 없어 실행 검증 필요). 플러그인 0.2.1은 업스트림 최신이고 관련 수정·이슈 없음.
- **`--resume`이 실패해도 종료 코드가 0으로 나온다.** 브리지 쪽 문제인지 그록 CLI 쪽인지 아직 안 밝혔다. 지금은 `git status`로 파일 변경 여부를 직접 확인하는 것으로 우회하고 있다. delegation-integrator가 원인을 확인하고, 고칠 수 있는 자리인지(하네스인지 플러그인인지) 판단해야 한다.
