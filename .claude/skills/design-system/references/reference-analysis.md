# 참고 디자인에서 스타일 값 뽑기

참고 사이트·스크린샷·색 값·프리셋에서 색·서체·둥글기 같은 값을 뽑아, 1·2층 토큰의 출발값으로 삼는 방법이다. 고르는 법 → 값 뽑는 법 → 분석 항목표 → 토큰에 잇는 법 → 금지 차례로 읽는다.

## 1. 이 문서를 언제 쓰나

- **참고에서 값을 뽑을 때** — idea-to-mvp 2단계 입구(`2-mockup.md` §2.2)에서 참고 디자인을 받아 브리프에 적을 때, 이미 지은 프로젝트의 브랜드를 바꿀 때(리브랜딩).
- **뽑아 둔 값을 토큰으로 옮길 때** — 브리프 「4. 확정 브랜드 자산」의 「우리가 쓰는 값」 표를 1층 램프·2층 shadcn 변수로 옮길 때 (§5). idea-to-mvp에서는 5단계 디자인 시스템 baseline(`5-frontend-build.md` §2.5.3)이 이 자리다.

참고를 읽는 일이지 우리 화면을 판정하는 일이 아니다 — 남의 사이트를 브라우저로 열어도 「화면 검증은 사람 몫」 원칙과 부딪히지 않는다.

**값의 정본** — 뽑은 값은 사람이 읽는 형식(hex·서체 이름·px·말)으로 적는 **출발값**이다. 1층 램프로 옮긴 뒤부터 정본은 1층이고, 화면 코드는 2층 이름만 쓴다 (SKILL.md 철칙). 기록 자리는 프로젝트가 정한다 — idea-to-mvp 프로젝트면 `mvp/design-brief.md` 「4. 확정 브랜드 자산」의 두 표(「우리가 쓰는 값」·「참고 기록」)다.

## 2. 고르는 법

**셋만 지킨다.**

- **같은 유형에서 고른다** — 유형은 [common-patterns.md](common-patterns.md) §1.1의 네 유형(SaaS · 커머스 · 마켓플레이스·O2O · 커뮤니티·SNS)이다. 쇼핑몰에 회사 소개 사이트를 참고하면 구성이 안 맞는다. 다른 유형의 사이트를 「구성」 축으로 고르면 한 번 짚는다 — 그래도 원하면 사용자 결정이 이긴다 (common-patterns.md §1 머리).
- **참고마다 닮을 축 하나** — 색 · 분위기 · 글자 · 밀도 · 구성 · 움직임 중 하나. 축마다 출처도 하나다. 두 참고가 같은 축을 잡으면 하나를 고르게 한다.
- **1~3개** — 많을수록 섞여 흐려진다. 상반된 것(예: 촘촘한 표 화면 + 여백 큰 소개 화면)은 같이 고르지 않는다.

**갤러리는 고르는 곳이지 입력이 아니다** — 사용자가 갤러리에서 골라 §3의 네 입력 중 하나로 넘긴다. 문서에는 최상위 주소만 둔다. 유형별 분류 주소는 사이트 구조가 자주 바뀌니, 필요할 때 그 사이트에서 찾아 짚어 준다 (바깥 사이트를 여는 일이라 §3 재시도 한도를 따른다).

| 갤러리 | 주소 | 로그인·유료 | 무엇을 보나 | 넘기는 법 |
|---|---|---|---|---|
| Mobbin | https://mobbin.com | 로그인 필요, 많이 보려면 유료 | 실제 앱 화면을 앱·화면 종류별로 모은 곳. 같은 업종 앱의 첫 화면·목록 화면 | AI는 열지 않는다 — 사용자가 캡처해 이미지로 |
| Recent (옛 Godly) | https://recent.design | 공개 | 잘 만든 웹사이트 모음. 유형 분류로 좁혀 첫 화면 분위기 | 고른 사이트의 원래 주소를 주소로 |
| Land-book | https://land-book.com | 공개 (일부 기능은 로그인) | 소개 화면(랜딩) 모음. 분류로 좁혀 첫 화면 구성·글꼴 | 원래 주소를 주소로 |

## 3. 입력 네 종류와 값 뽑는 법

| 입력 | 하는 일 | 정확도 |
|---|---|---|
| 사이트 주소 | 브라우저 도구로 열어 계산된 스타일을 읽고, 같은 세션에서 화면 한 장으로 느낌을 본다 (아래) | 색·서체 이름·둥글기·그림자는 정확. 어느 요소가 강조색인지는 판단이 든다 |
| 스크린샷·이미지 | 화면을 보고 값을 눈대중한다 | 색은 압축·색 공간 탓에 어긋나고 서체 이름은 맞히기 어렵다. 분위기·밀도·구성은 잘 본다 |
| 색 값 | 받은 hex를 그대로 적는다 | 정확 |
| 프리셋 | 그 프리셋이 정한 색 값을 그대로 옮긴다. oklch면 hex로 바꾸고 괄호에 원값 | 정확 |

**누가 뽑아도 사용자가 직접 준 값(색 값·서체 이름)이 이긴다.**

**사이트 주소 — 값은 계산된 스타일로, 느낌은 화면 한 장으로**

- 실제 적용된 CSS 값을 요소별로 읽는다 — 몸통 배경색(배경) · 본문 글자색(글자) · 주 버튼이나 링크의 배경색(강조) · 성공·위험 표시가 보이면 그 색 · 제목과 본문의 `font-family` · 카드와 버튼의 `border-radius` · 카드의 `box-shadow` · `:root`에 선언된 CSS 변수(이름에 primary·brand가 들어간 것). 화면에 없는 값(예: 첫 화면에 위험 표시가 없음)은 지어내지 않고 「관찰 못 함」으로 적는다.
- 같은 세션에서 화면 한 장을 찍어 분위기·밀도·첫 화면 구성을 본다. 한 번 열 때 둘 다 하면 추가 비용이 거의 없다.
- **연 조건을 값과 함께 적는다** — 라이트·다크, 창 폭. 운영체제 다크 모드·A/B 실험(사람마다 다른 화면을 보여 주는 실험)·로그인 전후에 따라 다른 값이 나온다.
- 브라우저 출력이 맥락을 많이 먹으니 서브 에이전트에 맡기는 게 맞다. 지시서에 아래 재시도 한도 줄·로그인 멈춤 줄·「재위임 금지」 줄을 넣는다.

**실패 모드**

| 실패 | 대응 |
|---|---|
| 로그인 벽 (Mobbin 등) | 열지 않는다. 로그인 화면이 뜨면 1회에 멈추고 사람에게 — 그 화면 스크린샷을 받아 이미지 갈래로 |
| 동적 테마 | 연 조건(라이트·다크, 폭)을 함께 적는다 |
| 서체 라이선스 | 이름은 정확히 나오지만 전용·유료 서체가 많다 → 무료 대체 (§6) |
| 봇 차단·캡차(CAPTCHA — 사람인지 확인하는 퍼즐) | 우회하지 않고 멈춘다 |
| 그림·캔버스로 그린 화면 | CSS에 값이 없다 → 화면 한 장으로 눈대중하고 표시를 붙인다 |

**재시도 한도** — 바깥 사이트를 여는 일이라 적용한다. 같은 실패 2회면 멈추고 보고한다. 401·403·404는 다시 하지 않는다. 로그인 화면이 뜨면 1회에 멈추고 사람에게 넘긴다. 반복된 실패 시도는 계정 제재로 이어진다.

**눈대중 표시** — 이미지에서(또는 CSS 값이 없어 화면에서) 뽑은 값은 「뽑은 값」 끝에 「(화면에서 눈대중)」을 붙인다. 이 표시가 빠지면 추정값이 확정처럼 흘러간다 — 토큰으로 옮길 때 사람이 한 번 더 볼 표시다.

## 4. 분석 항목표

참고를 이 여덟 칸으로 나눈다. 참고마다 닮을 축이 덮는 칸만 채운다.

| 닮을 축 | 덮는 항목 |
|---|---|
| 색 | 색 다섯 |
| 글자 | 서체 둘 |
| 분위기 | 둥글기 · 그림자 |
| 밀도 | 간격 · 밀도 |
| 구성 | 첫 화면 구성 |
| 움직임 | 움직임 느낌 |

| 항목 | 무엇을 적나 | 적는 형식 | 예 |
|---|---|---|---|
| 색 — 배경·글자·강조·성공·위험 | 역할마다 한 색 | hex(`#3182F6`처럼 16진수 여섯 자리 색 코드). 원래 oklch면 괄호에 원값 | 강조 `#3182F6` · 배경 `#FFFFFF` |
| 서체 — 제목·본문 | 서체 이름과 라이선스 | 이름 + 무료/유료, 유료·전용이면 대체 이름 | 「본문: Pretendard(무료)」「제목: ○○ Sans(전용) → Pretendard Bold로 대체」 |
| 둥글기 | 카드와 버튼의 모서리 | px 두 자리 | 「카드 16px · 버튼 10px」 |
| 간격 | 요소 사이 여유 | 「촘촘 · 보통 · 넉넉」 중 하나 + 관찰 예 | 「보통 — 카드 안 여백 약 20px」 |
| 그림자 | 카드·떠 있는 요소의 입체감 | 「없음 · 옅음 · 뚜렷」 + 관찰값 한 줄(있으면) | 「옅음 — 아래로 2px, 넓게 퍼진 연한 회색」 |
| 밀도 | 한 화면에 담기는 양 | 말 한 줄 | 「첫 화면에 목록 10건 이상, 본문 15px」 |
| 첫 화면 구성 | 최상단부터의 차례 | 문장 — 브리프 「5. UI 패턴 지정」에 「첫 화면: …(참고 1, 이유)」 | 「검색 → 카테고리 → 목록 (참고 1, 바로 고르게)」 |
| 움직임 느낌 | 무엇이 어떻게 움직이는지 | 말만 — 브리프 「8. 모션·인터랙션 방향」의 「참고 사이트」 행 | 「카드가 아래에서 순서대로 올라옴」 |

**제안 스타일 한 벌 짓기** — 참고가 없거나 참고가 덮지 않은 축이 있으면, AI가 서비스 유형과 브리프 「1. 브랜드 인상」 한 줄을 보고 같은 형식으로 채운다.

- **값이 있는 여섯을 값까지** — 색 다섯 · 서체 둘 · 둥글기 · 간격 · 그림자 · 밀도. 말 한 줄(「밝고 둥글게」)로 두면 화면을 그리는 쪽이 빈 곳을 제멋대로 채운다.
- 첫 화면 구성은 common-patterns.md §1 유형 기본값을 따르니 따로 적지 않는다. 움직임은 브리프 「8」의 기본값 그대로 둔다.
- 서체는 무료 서체로 고른다. 글자색은 배경과 4.5:1 이상이어야 하고, 강조색 위 글자도 4.5:1을 넘게 고른다(§5).
- 밀도는 유형을 따른다 — 훑는 화면은 촘촘하게, 읽는 화면은 넉넉하게 (common-patterns.md §1.2).
- 브리프 「7. 피할 것」(예: 보라 그라데이션류)에 걸리는 값은 고르지 않는다.
- 실제 서비스 이름을 붙이지 않는다 — 사용자가 그 서비스를 참고로 오해해 복제 쪽으로 끌린다.
- 지위는 `가정`이다. 사용자가 화면을 보고 괜찮다고 하면 `사용자 확정`으로 올린다.

## 5. 분석값 → 토큰

브리프의 값을 1층 원료와 2층 shadcn 변수로 옮기는 대응이다. 이름과 파일 모양은 [bootstrap-project.md](bootstrap-project.md) §1.2, 이름 문법은 [naming-taxonomy.md](naming-taxonomy.md) §2 유형표를 따른다.

| 분석 항목 | 1층 (원료) | 2층 (shadcn 변수) |
|---|---|---|
| 색 — 배경 | 회색 램프의 가장 밝은 단계(`--gray-0` 류) | `--background`. `--card`·`--popover`는 같은 램프 이웃 단계 |
| 색 — 글자 | 회색 램프 진한 쪽(`--gray-900` 류) | `--foreground`. `--muted-foreground`는 같은 램프에서 파생하고 배경과 4.5:1 |
| 색 — 강조 | 그 색을 600 근처에 둔 브랜드 램프 50~950 | `--primary`·`--primary-foreground`·`--ring`. 옅은 단계는 `--accent`·`--secondary` 후보 |
| 색 — 성공 | 초록 램프 | `--success`·`--success-foreground` — shadcn 세트에 없어 더한다 (naming-taxonomy.md §2 color/semantic 행) |
| 색 — 위험 | 빨강 램프 | `--destructive`와 짝. 장식에 쓰지 않는다 |
| 서체 — 제목·본문 | 폰트 변수(`--font-pretendard` 등). 로딩은 [font-loading.md](font-loading.md) §4 | 다리 블록 `--font-sans`(본문). 제목 서체가 다르면 `--font-brand` |
| 둥글기 | `--radius-base` = 카드 값 | `--radius` → `--radius-card`·`--radius-control`은 `calc()`로 파생 — 버튼 값이 나오게 차이를 고른다 (SKILL.md 동심원 radius 규칙) |
| 간격 | 4px 격자는 그대로 둔다 | 따로 변수 없음 — 셸 거터(`--space-screen-x`)와 부품 `size` 기본값을 고르는 근거. adapter 적용 규칙 요약에 한 줄 ([bootstrap-project.md](bootstrap-project.md) §4) |
| 그림자 | 그림자 원료 | 다리 블록 `--shadow-card` 등 (naming-taxonomy.md §2 shadow 행) |
| 밀도 | 타입 스케일의 본문 크기(`--b1-base`) | `text-b1`. 화면 단위 조정이 필요하면 naming-taxonomy.md §2의 스코프 클래스 |
| 첫 화면 구성 | 토큰 아님 | 토큰 아님 — 화면 인벤토리의 홈 항목이 받는다 |
| 움직임 느낌 | 말로 적은 느낌을 움직임 값으로 바꿀 때 만든다 (idea-to-mvp는 5단계 `5-frontend-build.md` §2.5.7) | `--duration-*`·`--ease-*` ([bootstrap-project.md](bootstrap-project.md) §1.4) |

**강조색 하나에서 브랜드 램프 50~950 만들기**

1. hex를 oklch로 바꾼다 — L(밝기)·C(채도)·H(색상) 세 값이 나온다.
2. **H는 고정**하고 단계마다 **L만 바꾼다** — 50이 가장 밝고 950이 가장 어둡다. C는 양 끝(50·950)에서 줄인다. 양 끝에서도 채도를 그대로 두면 색이 탁하거나 형광처럼 뜬다.
3. 원래 색은 600 근처에 둔다. 원래 색의 밝기가 600 자리에 비해 너무 밝거나 어두우면, 그 밝기에 가까운 단계에 둔다 — 원래 값을 억지로 600에 맞추지 않는다.
4. 이미 채택한 1층 램프가 있으면 새로 만들지 않고 가장 가까운 단계에 맞춘다 — 단계를 새로 만들지 않는다.

**`-foreground` 짝 대비 확인** — `--primary` 위 `--primary-foreground`, `--background` 위 `--foreground`·`--muted-foreground`가 모두 4.5:1 이상이어야 한다. 강조색이 밝아 흰 글자가 4.5:1에 못 미치면 `--primary`를 한 단계 진한 쪽(700)으로 잇거나 글자를 진한 색으로 바꾼다. 브리프 값을 고치는 게 아니라 잇는 단계를 고르는 일이다.

## 6. 금지

- **통째 복제 금지** — 참고의 로고·그림·사진·문구·화면 배치를 가져오지 않는다. 뽑는 건 값(색·서체 이름·px)과 말로 적은 느낌뿐이다. 문구·말투는 보이스 앤 톤으로 들어오지 않는다.
- **유료·전용 서체는 무료 대체** — 같은 계열(고딕·명조 등)이고 굵기 폭이 비슷한 무료 서체를 고른다. 원래 이름과 대체 이름을 같이 적는다.
- **섞어 평균 내지 않는다** — 축마다 출처 하나. 두 사이트의 강조색을 섞어 중간색을 만들지 않는다.
- **로그인이 필요한 화면은 열지 않는다** — 사람이 캡처해 이미지로 준다.
- **눈대중 값을 확정처럼 적지 않는다** — 「(화면에서 눈대중)」 표시를 붙인다 (§3).
